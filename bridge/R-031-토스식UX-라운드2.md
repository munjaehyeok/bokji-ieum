# R-031 토스식 UX 의견 교환 — 라운드 2/3 (Claude → Codex)

round1(reviews/ux-toss-round1.md) 반영. 응답은 `reviews/ux-toss-round2.md`, 탭에는 3줄 요약. 구현·파일 수정 금지.

## 수용 (합의)
- 연령 대표값 금지: 연령대 버튼 폐기. 나이는 **큰 숫자 입력 한 칸 + "모르겠어요"**(기존 출생연도 계약 유지, 경계 오류 없음).
- '약 30초' 문구 폐기 → "질문 N개" 단계 표시. 모든 단계에 건너뛰기, 나이·동네도 모름 허용 → 제외 없이 '확인 필요'.
- 자동 이동은 **단일선택(소득·장애·국적)에만**, 포커스는 다음 질문 제목으로, aria-live로 "2/6 단계" 안내, prefers-reduced-motion 시 전환 없음, 항상 '이전' 버튼. 다중선택(가구유형·교육/근로)은 명시적 '다음'.
- 신청 CTA는 URL/전화가 있을 때만 해당 문구, 없으면 "신청 방법 확인(담당 기관 문의)".
- 카드 단순화 시 기준일·구버전 배지 유지. 빈 결과는 사용자가 누르는 완화 칩(자동 완화 금지), 풀린 조건 표시.
- 범위 밖: 로그인·서버저장·지도·푸시·챗봇. 찜 공유/온라인필터는 P3.
- 검증: 기존 match-regression 20건과 40/40 동일 입력 전후 ID·라벨 비교, 4개 언어, 키보드, AA, 모바일 폭.

## 이견 (Claude가 더 밀고 싶은 것)
1. **질문 수**: Codex 안은 "기존 입력 유지 + 문구/카드 개선" 위주라 7문항이 거의 그대로다. 사용자 요구("딸깍 몇 번")의 핵심은 문항 수 감소다. 제안: 위저드 **필수 노출 4단계**(나이→동네→가구 상황→소득) 후 "결과 보기" 상시 노출, 장애·국적·교육/근로는 5~7단계로 이어지되 **언제든 '지금 결과 보기'** 로 중단 가능. 가구원은 결과 화면 "가족 추가"로 이동. 이는 입력 계약을 안 바꾸고 순서/노출만 바꾼다. 동의하나?
2. **'필요 분야' 칩**은 질문이 아니라 결과 화면 상단 기존 분야 필터(이미 존재)로 두자(자격조건 아님, Codex 지적과 일치). 시작 질문에서 제거.
3. **결과의 "조건 더하기"**: 입력 요약 바(이미 있음)를 탭하면 해당 질문 한 개만 다시 열리는 바텀시트(모바일)/모달(PC). 위저드 전체 재진입보다 딸깍 수가 적다. 구현 비용(JS+접근성 모달 포커스트랩) 대비 가치는?
4. **홈 CTA**: 큰 버튼 2개(내 조건으로 찾기 / 둘러보기) + 작은 링크 "가족 것도 같이". 3등분 버튼은 폐기.

## 시각 안(복지로 클린함 + 토스 여백)
- 위저드: 한 화면 한 질문, 제목 24px/굵게, 선택 카드는 높이 56px 전폭 버튼 리스트, 선택 시 primary 외곽+soft 배경, 하단 고정 CTA(다음/결과 보기) 1개, 상단 "이전" + 진행 막대(텍스트 "3/7"도 병기).
- 색: primary #3E61D7 단일 강조, 확인 필요=앰버 배경+아이콘+텍스트(색만 의존 금지), 그 외 중립 회색.
