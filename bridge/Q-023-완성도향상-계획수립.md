# Q-023 완성도 향상 계획 수립 요청 (디렉터 역할)

사람 지시: "위험한 부분 수정 아이디어는 코덱스가 내고, 완성도를 높이고 싶으니 전부 계획 세워서 진행". 
근거: 네가 쓴 `reviews/review-R-022.md` (위험 6개 + 액션 10개). 읽기 전용: `reviews/direction-023.md` 에만 쓰고 다른 파일은 수정·삭제하지 말라.

## 요청
1. R-022의 위험·액션 전부를 **실행 계획**으로 만들어라. 각 작업: ID(T1…), 종류(구현/문서/검증/사람전용), 소유 경로, 의존, 완료 기준(증거 형태), 구체적 수정안(문구는 before→after 제안 포함). `python3 plan-check.py PLAN.md` 형식에 맞는 표를 파일 끝에 붙여라.
2. **Claude(구현 에이전트)가 저장소 안에서 끝낼 수 있는 것**과 **사람 전용**(복지온·복지로 직접 비교 시연, 시 부서 협의/최신본 요청 발송, 사용성 테스트 실행, 외국인 수치 출처 선택, 배포 승인)을 분리하라. 사람 전용은 사람이 바로 할 수 있게 체크리스트(입력 조건, 캡처 항목, 기록 양식)로 만들어라.
3. 숫자 통일(T-숫자): 외국인 72,424/12.3% vs 40,493/7.2%, 744 vs 792, 민간 544 vs 546, 2026 기준일 47 vs 55 — 저장소에서 확인 가능한 것은 확정 값과 SQL/문서 근거를 적고, 확인 불가는 "사람 결정"으로 표시.
4. 과장 문구(README '목록 검색에 그친다', '맞는 것만', '정확도 100%', '최신 792건')의 교정 문구안과 수정 대상 파일 전체 목록(grep으로 확인)을 제시하라.
5. 공개 전 보안: 고정 관리자 계정(AdminInitializer) 처리 방안. 팀 확정과 충돌하지 않는 최소안을 제시하고, 동작 변경이라 사람 승인이 필요한지 표시하라.
6. 본문 대조(0건): 위험도 우선순위 기준, 표본 크기, 기록 양식(본문검증대장.csv 규칙)을 정하라. 외부 사실 확인이 필요한 부분은 Claude가 웹에서 못 하면 사람 전용으로.
7. 실행 순서(wave)와 각 wave 끝의 게이트(데이터 게이트·스모크·리뷰 R번호)를 정하라. 한 번에 5작업 이하.

## 제약
팀 확정(시흥시만, 태깅 원칙, 소득 결정표) 유지. 배포·병합·푸시는 사람 승인 후. 동작·데이터를 바꾸는 작업은 멱등 SQL+근거 동반. 새 기능 확장보다 증거·정직한 표현·완성도 우선.
