## P1-1 소득 순위 (resource-mapper.xml:47, :115) — **기각 제안 (사람 확인 필요한 P1 기각)**
- 사실: 매퍼가 `income_rank`로 가점·제외를 하는 것은 맞다. 그러나 이것은 설계서 `docs/설계/03-매칭-엔진-설계.md`(결정표, "진실의 원천", 줄 93·110~126)가 정한 동작이다. 사용자가 4번 스텝에서 소득구간을 직접 고르고, 자원의 `income_rank`는 소득 기준이 구간(수급/차상위/중위100/150)으로 명시된 경우에만 채운다 (실데이터 182건, 24.5%, `docs/데이터/태깅-현황.md`).
- "소득은 확인필요 플래그만"이라는 AGENTS.md 문구는 **내가 옮겨 적다 과일반화한 오류**다. 게이트1 D4의 실제 교훈은 "구간으로 환원 안 되는 기준(기초연금·건강보험료·중위 180%)은 rank를 비우고 income_uncertain='Y'"였다. 이 문구를 바로잡았다.
- 사용자가 모름(0)이면 제외하지 않고 확인필요로 둔다(매퍼 :115 `#{cond.incomeRank} = 0`). 따라서 "틀리게 제외 금지"와 충돌하지 않는다고 본다. 반론이 있으면 구체적 사례(자원 id, 입력 조합)를 달라.

## P1-2 일부 대상 연령을 전체 필수로 저장 — **인정, 수정 중**
- 확인: 'gov24 동네관리소 간단 집수리 지원' age_min=65, 대상은 "수급자, 독거노인(만65세이상), 차상위…" → 65세 미만 수급자가 나이로 제외됨.
- 같은 유형 추가 발견: '장애인 전동보장구 배상책임보험' age_min=65 + disability='Y', 대상은 "등록 장애인 **또는** 만65세 이상" → OR을 AND로 저장(D2와 같은 실수). 65세 미만 장애인도, 65세 이상 비장애인도 제외됨.
- 조치: 두 건 age_min·disability 해제 + uncertain_note (멱등 SQL `reliability-tagging.sql`). 신규 48건(API 24 + gov24 24)은 전수 점검했고 나머지 연령 태그는 '무료급식 지원'(60세 이상 노인, 맞음)과 '효도수당' 2건뿐이다.
- 질문: '효도수당' age_min=70은 "1세대가 만 70세 이상인 3세대 가구"라 **신청자가 직계비속일 수 있다**. 수혜자 기준 연령을 신청자 필터로 쓰는 게 오제외인가? 내 판단은 해제+확인필요(보수적)인데 네 의견은?

## P1-3 본문 미대조인데 기준일만 최신화 — **인정, 단 설계는 합의 필요**
- 확인: gov24/API 매칭 UPDATE 19건(gov24 16 + API 3)은 본문 비교 없이 data_base_date를 원천 수정일로 올렸다. 자원 315는 대상명이 '산모·신생아 건강관리 지원**(추가형)**'이라 동일 사업인지부터 불확실하다.
- 이 날짜가 old_data 배지와 최신순 정렬에 쓰이므로 본문 최신성을 과장한다. 인정한다.
- 제안(최소안): 본문을 대조하지 않은 매칭 건은 data_base_date를 되돌리고(원본 2022 보존), 존속·연락처 확인은 last_verified_date로만 남긴다. 컬럼 추가(본문확인일 별도)는 T0 스펙에서 결정하자.
