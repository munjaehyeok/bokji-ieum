# Q-024 탐색 모드 방향 검토

## 결론

조건 입력 없이 시흥시 자원을 둘러보는 `/resources`는 가치가 있다. 다만 제안안은 일부 메타데이터를 단정적인 자격 필터로 읽히게 만들고, `nationality=F`를 다문화·탈북민과 한 축으로 묶어 오제외·오분류 위험을 높인다. 탐색 결과는 자격 판정이 아니라는 안내만으로 데이터 누락이 해결되지는 않으므로, 필터마다 데이터가 의미하는 범위와 미분류 항목의 처리를 정하고 진행한다.

## 설계 수정 지시

1. **목록과 판정을 구분한다.** `GET /resources`는 상태가 활성인 시흥 자원만 반환한다. 쿼리스트링으로 필터 상태를 재현하고, 필터 결과가 자격 적합·부적합 판정이 아님을 목록과 결과 건수 주변에 표시한다. 조건 입력은 “나에게 맞는지 확인”으로 연결한다. 기본값은 필터 없음이며 792건 전체를 볼 수 있어야 한다.

2. **분야·가구 필터는 의미를 보존한다.** 관심주제는 DB의 9개 `category`를 그대로 사용한다. 선택한 여러 값은 같은 필터 축 안에서는 OR, 서로 다른 축 사이는 AND로 한다. 저소득은 확인된 소득 구간 태그를 기준으로 삼고, `income_uncertain='Y'` 또는 구간 미분류 자원은 별도 “기준 확인 필요”에 포함하거나 기본 포함하는 선택을 둔다. 장애인은 `disability='Y'`; 한부모·조손, 다자녀, 다문화, 북한이탈, 1인가구는 각각 실제 `household_types` 코드에만 매핑한다. `nationality='F'`는 다문화·탈북민 필터에 섞지 말고 별도 “외국인 대상 태그”로 분리한다. 앞선 리뷰에서 다문화가족과 귀화자 범위가 불명확한 F 태그가 드러났으므로, 해당 태그의 정확도를 확인하기 전에는 이를 적극적인 제외 기준으로 쓰지 않는다.

3. **생애주기는 명시적 연령 범위만으로 계산한다.** 생애주기 구간은 경계를 문서화한다(제안값: 0–5, 6–12, 13–18, 19–39, 40–64, 65+). 자원 범위와 생애주기 범위가 실제로 겹치는지 검사하고 ±1 관용은 적용하지 않는다. `PREG`는 임신·출산 가구 코드이며 나이 구간과 별도 필터로 둔다. 이름·신청권자의 단어 정규식은 AGE_HINT의 “확인필요” 표시를 위한 휴리스틱이지, 확정된 생애주기 적격성 태그가 아니다. 사용할 경우 “대상 문구에서 찾은 참고 항목”으로 분리하고 기본 생애주기 필터 결과를 단정하지 않는다. 미기재 자원은 별도의 “연령 정보 미분류도 포함” 옵션을 기본 켜서 사용자가 누락 가능성을 인지하고 좁힐 수 있게 한다.

4. **검색과 온라인 신청 문구를 정확히 한다.** 검색어·제외어는 길이와 개수를 제한하고 바인딩 파라미터를 쓰며 `%`, `_`를 리터럴 검색으로 이스케이프한다. 제외어는 검색어가 제외어보다 우선하지 않도록 정의한다. `apply_url` 존재만으로 온라인 신청이 가능하다고 볼 수 없다(상세 안내 URL일 수 있음). `apply_method`의 명시적 온라인 신청 정보와 URL을 함께 확인해 필터 이름은 “온라인 신청 정보 있음” 등으로 제한적으로 쓴다. 신청 링크가 단순 안내 페이지일 때는 실제 신청과 구별한다.

5. **최신순·인기순을 과장하지 않는다.** 최신순은 기준일 NULL 행의 위치와 동률 정렬을 고정한다. 인기순은 익명 상세 조회 D 이벤트의 집계이며 신청 수나 선호도와 다르다. 충분한 최근 표본이 없을 때는 기본순으로 대체하고, 작은 모집단·짧은 집계기간을 UI에 밝힌다. 기본 정렬은 이름/분야 등 안정적인 순서로 두고 모든 정렬에 고유 ID 동률키를 둔다.

6. **찜은 브라우저 안에 제한한다.** 즐겨찾기 ID를 `localStorage`에 저장하고 목록 진입 시 길이·중복·활성 ID를 검증한다. ID를 무제한 `?ids=`로 옮기지 않는다. 저장소를 사용할 수 없거나 목록이 비었을 때도 안내를 제공한다. 로그아웃·계정 간 동기화가 없다는 점을 설명한다.

7. **지도는 이번 범위에서 제외해도 된다.** 조사 자료상 좌표 데이터가 없고 시흥 시설의 위치 확인·좌표 검증이 별도 작업이다. 주소를 지오코딩해 정확한 위치처럼 보이게 하지 않는다. 후속 범위는 주소/좌표 출처, 좌표 검증, 키·약관, 모바일 접근성까지 별도 계획으로 남긴다. 복지위기알림·신고는 조사 자료와 프로젝트의 시흥 자원 탐색 목적을 고려해 이번 기능에서 제외한다.

8. **기존 상세 판정은 유지한다.** 상세 페이지의 비교표·신청 방법을 제거하지 말고, 조건 없는 탐색에서는 판정표를 표시하지 않는 현 구조를 유지한다. 담당부서·주기·제공유형 등 기존 데이터를 보강하되 빈 값은 추정해 채우지 않는다. 브랜드는 복지이음으로 유지하며 복지로의 로고·문구·이미지는 사용하지 않는다.

## 수락 기준

### SQL·라우트 회귀

- 필터 없는 기본 호출은 활성 자원 전체 792건을 페이지로 나누어 노출하고, 종료·숨김 자원은 반환하지 않는다. 페이지를 이동해도 중복/누락이 없고, 기본순·최신순·인기순은 동률에서 항상 안정적으로 정렬된다.
- 단일 category, 복수 category OR, 서로 다른 축 AND를 각각 검증한다. 잘못된 코드값은 무시하거나 400으로 일관되게 처리하고 SQL 오류를 내지 않는다.
- 각 `household_types` 코드(ONE/SPAR/MCHD/MCUL/NKOR/PREG)의 양성·음성 사례, 복수 선택 OR, 미분류값 처리, `nationality=F`가 다문화/탈북민 축에 섞이지 않는 사례를 검증한다.
- 나이 구간 경계(0/5/6/12/13/18/19/39/40/64/65), 부분 구간 겹침, 최소/최대 단독값, 나이 미기재 포함/제외 옵션을 검증한다. ±1 확장을 하지 않는다. PREG는 생애주기 나이와 별도 축으로 확인한다.
- 저소득 rank 1·2, 그 외 rank, `income_uncertain='Y'`, NULL의 처리를 계약대로 검증한다. 불명확한 소득 기준이 명시적 저소득 결과에서 조용히 사라지지 않는다.
- 검색 필드(name/support_content/org_name/applicant), 다중 검색어, 제외어, `%`·`_`·따옴표·한글·빈 검색을 검증해 와일드카드 우회나 SQL 주입이 없다.
- 온라인 신청 필터는 정책상 정한 `apply_method`/URL 조건에만 일치한다. 단순 출처·상세 안내 URL만 있는 사례를 온라인 신청 가능으로 잘못 표시하지 않는다.
- 모든 쿼리는 바인딩하고, 조회 전 범위가 active + 시흥 자원인지 확인한다. 인기순은 D 이벤트 집계만 사용하고 최근기간·최소 표본·저표본 fallback·동률 규칙을 검증한다.
- 페이지네이션·정렬·필터 변경은 다른 쿼리 상태를 보존한다. 빈 결과, 긴 검색어, 중복 파라미터, 음수/큰 페이지, 잘못된 ID 등 경계를 다룬다.

### 화면·스모크

- `/resources` 직접 접근, 홈에서 탐색 진입, 필터 적용/초기화, 결과 페이지 이동, 상세 이동 후 목록 복귀, 나에게 맞는지 확인 진입을 끝까지 확인한다.
- 카드에 확인된 분야·가구 태그·담당부서·주기·제공유형·문의·자료 기준일만 표시하고, 오래된 자료 배지와 탐색/판정 차이를 분명히 한다. 필드 누락 시 추정값을 보여 주지 않는다.
- 390px와 데스크톱 폭에서 가로 넘침이 없고, 필터는 키보드 조작·레이블 연결·포커스 표시를 갖춘다. 결과 건수 변경을 보조기술이 알 수 있다.
- ko/en/zh/vi에서 필터·정렬·페이지네이션·빈 상태·경고 라벨이 누락되지 않고 레이아웃이 깨지지 않는다. 데이터 본문 번역이 없으면 임의 번역 대신 기존 동작을 유지한다.
- 찜은 저장소 차단·손상·오래된 ID에서도 페이지 오류 없이 복구 안내를 주고, 서버에 개인 프로필이나 찜 기록을 보내지 않는다.
- 콘솔 오류 0, 예상치 않은 4xx/5xx 0, 핵심 사용자 흐름 스크린샷과 결과를 스모크 파일에 기록한다.

## 미확정 범위

복지로 조사 메모는 로그인·지도·모의계산을 직접 확인하지 않았고, 복지로의 시흥 필터 건수와 민간 자원 포함 여부도 미확인이라고 적는다. 비교 문구는 관찰된 목록 구조에만 한정한다. 지도 및 위기알림·신고는 이번 시흥 792건 탐색 기능에 포함하지 않는다.
