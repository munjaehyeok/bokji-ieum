# R-036 토스식 시각 검토 — 라운드 2

## 검토 범위와 근거

- R-035/`reviews/ux-loop/round-1.md`에서 제안한 헤더·히어로·질문·결과/탐색의 시각 변경을 읽고, 현재 HEAD 화면을 직접 비교했다.
- Chrome 라이브 확인: 홈, `/match?step=4`, `/match/result`, `/resources`. 1710px 기본 화면 및 390×844 모바일 뷰에서 네 경로를 시각 확인했다. 결과 화면에는 브라우저 세션에 이미 있던 36세 조건(1990년생) 결과가 표시됐다. 이 검토에서 폼을 제출하거나 선택값을 변경하지 않았다.
- 별도 모바일 캡처 파일은 저장하지 않았다. 질문 화면 상단 및 하단, 결과 화면, 탐색 화면, 홈을 모바일에서 직접 확인했다. 데스크톱에서는 홈·질문·탐색과 기존 결과 화면을 확인했다.
- 브리지에 적힌 9개 화면 × 2폭의 대비/가로 넘침 검사 결과(AA 실패 0, 넘침 0)는 구현자 보고로 참고했다. 직접 캡처에서는 중국어 홈 제목이 잘리는 사례를 확인했다. `.bk-hero { overflow:hidden }` 때문에 화면 밖 텍스트가 잘려도 가로 넘침 검사에는 잡히지 않을 수 있다.

## 남은 격차와 수정 제안

### P1 — 중국어 홈 제목이 실제로 잘림

- 근거: 390px 중국어 홈 스크린샷에서 제목 `一分钟内找到适合您的始兴市福利`의 오른쪽 문장이 화면에 나타나지 않는다. 접근성 트리에는 전체 텍스트가 있지만, 시각적으로는 `.bk-hero` 경계에서 잘린다.
- 대상: `src/main/webapp/static/css/bokji.css`의 `.bk-hero h1 { word-break: keep-all; text-wrap: balance; }`, `.bk-hero { overflow:hidden }`, 그리고 모바일 `.bk-hero` 규칙.
- 제안: 중국어(`html[lang="zh"]`)에서는 제목 줄바꿈을 기본 CJK 규칙으로 돌리고 `overflow-wrap`이 긴 문자열을 처리하게 한다. 잘림을 고치기 위해 `.bk-hero`에 수평 스크롤을 추가하지 않는다. 390px에서 중국어·베트남어·영어·한국어 제목 전체가 패널 안에 보이는지 확인한다.
- 보고된 “가로 넘침 0”과 시각 잘림은 다른 상태다. 콘텐츠 경계가 실제 글리프를 숨기지 않는지도 캡처 검증에 포함한다.

### P1 — 히어로는 여전히 카드형 덩어리

- 근거: 데스크톱 홈은 제목·보조문구·CTA 좌측 정렬과 우측 일러스트를 갖춰 라운드 1보다 가까워졌다. 다만 첫 화면 높이의 대부분을 차지하는 큰 틴트 박스, 제한된 폭, 둥근 24px 모서리가 기준 Toss 화면의 열린 회색 배경·넓은 여백과 다르다.
- 대상: `src/main/webapp/static/css/bokji.css`의 `.bk-hero`, `.bk-hero h1`, `.bk-hero-art`; `src/main/webapp/WEB-INF/views/index.jsp`의 `.bk-hero` 구조.
- 제안: 컨테이너의 카드 윤곽을 줄이고 틴트 배경을 화면 폭 전체에 이어지게 한 뒤, 내부 텍스트/일러스트만 공통 콘텐츠 폭에 맞춘다. 세로 패딩을 줄여 ‘한 장의 배너 카드’ 느낌을 낮춘다. 타이틀·CTA 기준선과 독립된 일러스트는 유지한다.

### P2 — 모바일 공통 헤더와 고정 페이지 이동 버튼

- 근거: 모바일 헤더에서 브랜드/검색, 언어/글자 크기, 메뉴의 세 줄이 먼저 차지한다. 질문 화면 상단에서는 우측 하단 고정 페이지 이동 원형 버튼이 다음 질문 조작 영역 가까이 겹쳐 보인다.
- 대상: `src/main/webapp/static/css/bokji.css`의 `@media (max-width:575.98px)` 헤더 규칙과 `.bk-float-controls`.
- 제안: 모바일에서 검색은 접근 가능한 버튼/접힘 패널로 압축할 수 있으나 검색 제출 기능과 4개 언어, 글자 크기 조절은 계속 한 번의 짧은 조작으로 찾게 한다. 고정 페이지 이동 버튼은 화면 하단의 입력/다음·건너뛰기 조작과 겹치지 않도록 배치하거나 폼 조작 중에 위치를 달리한다. 변경 후 390px 질문 상단·하단을 다시 본다.

### P2 — 결과 화면 모바일 필터와 건수 줄바꿈

- 근거: 390px 결과 화면에서 분야 버튼들이 여러 줄로 쌓이고, 결과 건수의 마지막 단위 ‘건’이 단독 줄로 떨어진다. 정보는 모두 보이나 결과 목록 도달 전에 세로 공간을 많이 쓴다.
- 대상: `src/main/webapp/WEB-INF/views/match/result.jsp`의 `#bkCatFilter`, `#bkSortToggle`, `#bkCount`; `src/main/webapp/static/css/bokji.css`의 `.bk-filter`, `.bk-summary` 및 결과 제목 규칙.
- 제안: 3열 또는 2열의 규칙적인 필터 그리드/그룹으로 정리하고 현재 선택 상태를 분명히 한다. `#bkCount`는 모바일에서 글자 크기나 폭을 조절해 숫자와 단위를 가깝게 묶되, “조건에 어긋나는 점 없음/추가 확인 필요”의 의미를 줄여 쓰지 않는다. 날짜·오래된 자료·확인 필요 표기는 접거나 제거하지 않는다.

## 요청 판단

- **데스크톱 ‘처음부터 다시’ 숨김: 허용.** 라이브 헤더에 홈 로고와 `홈`, `조건으로 찾기`, `둘러보기`가 남아 중복 이동 링크가 아니어도 핵심 탐색이 가능하다. 단, 현재 JSP의 해당 링크는 `href="/"`이며 실제로 조건을 초기화하지 않는다. 따라서 숨긴 링크가 세션 조건까지 지우는 ‘새로 시작’ 기능을 대체한다고 설명하면 안 된다. 사용자가 새 조건으로 시작하도록 돕는 기능이 요구되면 별도 명시적 경로와 실제 초기화 동작을 정의해야 한다.
- **390px 헤더: 현재 기능 배치는 동작하지만 세로 점유는 큼.** 검색·언어·글자 크기·메뉴를 유지하면서 1~2단으로 줄이는 다음 개선이 유효하다.
- **홈을 Toss에 더 가깝게 할 남은 점:** ① 히어로 배경을 컨테이너 밖까지 열기 ② 큰 둥근 패널과 높은 세로 패딩 낮추기 ③ 모바일 각 언어의 제목 줄바꿈 보장하기. Toss 로고/서체/이미지/문구 복제는 금지한다.

## 하지 말아야 할 것

- 검색·4개 언어·글자 크기 조절을 삭제하거나 모바일 깊은 메뉴 뒤로 숨기지 않는다.
- 결과의 `일치`, `추가 확인 필요`, 오래된 자료/사업내용 기준일을 실제 자격 확정 또는 현재 내용 검증처럼 보이게 바꾸지 않는다. 연락처 확인일과 사업내용 기준일을 하나의 날짜로 합치지 않는다.
- 입력 7단계, 조건/자원 매칭 계약, 범위(시흥시 자원만)를 시각 개편과 함께 변경하지 않는다.
- AA 대비, 키보드 포커스, 터치 영역을 희생해 헤더나 필터를 압축하지 않는다. Toss 상표 자산을 쓰지 않는다.

## 다음 슬라이스와 총평

다음 구현은 **홈 모바일 제목 줄바꿈 P1 → 열린 히어로 캔버스 P1 → 모바일 헤더/고정 버튼 P2 → 결과 필터·건수 P2** 순서로 권고한다. 현재 데스크톱 헤더와 질문 UI는 기준의 밀도·위계에 상당히 가까워졌고, 결과·탐색 카드의 그림자 축소도 효과적이다. 이 라운드의 핵심 blocker는 중국어 제목이 보이지 않는 현상이다. 수정 후 홈·질문·결과·탐색의 데스크톱/390px 캡처를 같은 화면 위치에서 다시 비교하고, 특히 긴 중국어/베트남어 제목과 고정 버튼 겹침을 확인해야 한다.
