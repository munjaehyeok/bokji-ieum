# R-035 토스식 시각 검토 — 라운드 1

## 검토 범위와 근거

- 비교 기준: `reviews/ref-local/toss-home-top-1502.jpg`, `reviews/ref-local/ours-home-top-1502.jpg`, 역할 문서 `reviews/ux-loop/REVIEWER-ROLE.md`.
- 기존 Chrome의 복지이음 홈 및 `/match/result`를 읽기 전용으로 확인했다. 홈은 제목·검색·언어·글자 크기·주요 메뉴를 제공하고, 히어로와 소개 섹션이 이어진다. 결과 화면은 50건 일치/562건 추가 확인 필요, 자원 기준일·오래된 자료 표시를 노출한다.
- `/match`, `/resources`는 로컬 HTTP GET 200을 확인하고 JSP/CSS 구조를 읽었다. `/match/result`는 기존 브라우저 세션에서 표시됐으며, 세션 없는 직접 GET은 302였다. 질문·탐색 화면과 모바일 폭은 별도 시각 캡처하지 못했으므로 해당 항목은 마크업·반응형 CSS 기준의 잠정 점수다.
- 점수는 Toss의 구성·리듬·위계에 대한 근접도다. 구현 품질이나 사용자 접근성의 종합 등급은 아니다.

## 우선순위와 수정 제안

### P1 — 홈 헤더와 히어로의 구성부터 맞추기

- 대상: `src/main/webapp/WEB-INF/views/common/top.jspf`의 `.bk-head-main`, `.bk-head-tools`, `.bk-primary-nav`; `src/main/webapp/WEB-INF/views/index.jsp`의 `.bk-hero`, `.bk-hero-art`, `.bk-cta`; `src/main/webapp/static/css/bokji.css` 관련 규칙.
- 데스크톱에서는 로고·주요 메뉴·대표 CTA를 한 줄에 배치하고, 헤더의 검색·언어·글자 크기 기능을 밀도 낮은 도구 영역으로 재배치한다. 검색은 현재 입력 폼을 유지한 채 접힘/확장형으로 바꾸거나 메뉴 옆 짧은 입력으로 둘 수 있다. 언어 선택과 글자 크기는 상시 발견 가능하고 키보드로 조작 가능하게 남긴다. 기능 제거는 승인하지 않는다.
- `.bk-hero`를 카드처럼 둘러싼 경계·그림자 없이 중립 틴트 영역에 두고, `.bk-hero h1`, `.bk-hero .bk-sub`, `.bk-cta`를 좌측 기준선으로 정렬한다. 제목은 데스크톱에서 약 48px 수준의 선명한 위계를 주고, 일러스트는 삭제하기보다 축소·보조 배치해 정보와 CTA보다 먼저 눈에 띄지 않게 한다.
- `.bk-cta .bk-start-btn`은 현재의 큰 높이·반경을 줄여 컴팩트한 주/보조 버튼 쌍으로 보이게 한다. 주 행동은 조건 찾기, 보조 행동은 둘러보기로 구분하고 가족 조건 링크는 보조 텍스트 링크로 유지한다.
- 다음 단계에서 검색·언어·글자 크기 기능이 데스크톱과 모바일 모두에서 한 번의 짧은 조작 이내에 접근되는지 확인한다.

### P1 — 질문 화면의 진행 위계와 선택 컨트롤 정리

- 대상: `src/main/webapp/WEB-INF/views/match/form.jsp`의 `.bk-progress`, `.bk-step.active`, `.bk-choice-grid`, `.bk-choice`, `.bk-step-nav`; `src/main/webapp/static/css/bokji.css`의 같은 선택자.
- `.bk-progress`는 숫자/단계 텍스트가 먼저 읽히도록 단순화하고 진행 표시의 대비를 유지한다. `.bk-step.active`의 큰 카드 테두리와 그림자를 줄여 콘텐츠 영역을 가볍게 하고, 질문 제목·짧은 안내·선택지의 수직 간격으로 리듬을 만든다.
- `.bk-choice`는 동일 상태의 과도한 둥근 타일 느낌을 줄이고, 기본·선택·포커스 상태를 명확한 경계와 배경색 차이로 표현한다. `<label>`과 입력 연결, 44px 이상 조작 영역, `.bk-choice:focus-within` 가시성을 보존한다.
- 구현 순서에서 홈 다음 슬라이스로 진행한다. 단계 이동·건너뛰기 의미와 7단계 입력 계약은 건드리지 않는다.

### P1 — 결과 카드에서 안심/확인 필요/정보 최신도를 빠르게 구분

- 대상: `src/main/webapp/WEB-INF/views/match/result.jsp`의 `.bk-summary`, `#bkCatFilter`, `#bkSortToggle`, `.bk-group`, `.bk-card`, `.bk-tag-match`, `.bk-tag-check`, `.bk-badge-old`; `src/main/webapp/static/css/bokji.css` 결과 규칙.
- 현재 결과 목록은 많은 카드가 연속되고 제목·기관·요약·조건 라벨·기준일이 한 카드 안에 모인다. `.bk-card`의 반복 그림자와 패딩을 낮추고 제목/기관/요약/상태/기준일의 글자 크기와 여백을 분리해 스캔 순서를 만든다. 분야 필터와 정렬은 결과 건수 주변에서 한 그룹으로 정돈한다.
- `일치`는 “입력 조건에 어긋나는 점이 없음”이라는 의미로만 보이고 지원 확정으로 오해되지 않도록 최종 확인 안내를 결과 수와 상태 태그 가까이에 둔다. `확인 필요` 및 `오래된 자료`는 색상만으로 전달하지 말고 텍스트 라벨을 계속 노출한다. 2022 사업내용 기준과 2026 연락처 확인을 같은 최신성처럼 보이게 합치지 않는다.
- 기존 기준일, 확인일, 확인 필요 라벨, 매칭 결과 계약, 필터·정렬 동작은 유지한다.

### P2 — 탐색 필터와 목록의 반복 장식 줄이기

- 대상: `src/main/webapp/WEB-INF/views/resource/list.jsp`의 `.bk-explore-form`, `.bk-axes`, `.bk-fields`, `.bk-explore-bar`, `.bk-explore-list`, `.bk-xcard`; `src/main/webapp/static/css/bokji.css` 탐색 규칙.
- `.bk-explore-form`은 상단 굵은 선과 주변 경계 장식을 중복하지 않게 하고, 각 `.bk-axis`의 범주 제목과 입력 묶음을 명확히 정렬한다. 현재 화면에서 필터가 검색 결과보다 더 무거워 보이지 않도록 여백과 선의 대비를 낮춘다.
- `.bk-xcard`의 2열 목록은 제목·요약·기준일을 우선하고 메타 정보를 한 단계 낮춘다. 모바일에서 1열, 긴 한글/다국어 레이블 줄바꿈, 컨트롤 가로 넘침을 확인한다. 필터 항목이나 검색 기능은 숨기거나 제거하지 않는다.

## 진행 슬라이스

1. **홈**: 공통 헤더 밀도 조정 → 히어로 좌측 정렬·CTA 크기 조정 → 소개 섹션 배경 리듬 확인.
2. **질문**: 진행 표시와 질문 콘텐츠 위계 → 선택지/포커스 상태 정리.
3. **결과**: 요약·필터 배치 → 카드 정보 순서 → 오래된 자료/확인 필요 안내 가독성 확인.
4. **탐색**: 필터 범주 정리 → 목록 카드의 제목·요약·메타 위계와 반응형 확인.

각 슬라이스는 동일 화면을 데스크톱·모바일로 다시 캡처해 비교하고, 4개 언어, AA 대비, 키보드 조작, 가로 넘침과 기존 동작을 확인한 뒤 다음으로 진행한다.

## 하지 말아야 할 것

- Toss 로고·제품 서체·이미지·문구·상표를 가져오거나 시각 요소를 그대로 복제하지 않는다. 구성과 시각적 리듬만 참고한다.
- 검색, 언어 변경(한국어/영어/중국어/베트남어), 글자 크기, 가족 구성, 필터·정렬을 제거하거나 깊숙이 숨기지 않는다.
- 매칭·데이터 계약, 자격 분류, 정렬 의미를 바꾸지 않는다. “일치”를 지원 자격 확정처럼 표현하지 않고 “확인 필요” 및 오래된 본문 경고를 약화하지 않는다.
- AA 대비, 키보드 포커스, 터치 타깃, 다국어에서의 줄바꿈을 희생해 화면을 압축하지 않는다.

## 총평

현재 화면은 복지 기능과 상태 라벨은 충실하지만, 홈 첫 화면에서 큰 중앙 히어로와 두 줄 헤더가 강한 인상을 만들어 기준의 슬림한 내비게이션·좌측 텍스트 중심 리듬과 멀다. 우선 홈에서 헤더 밀도를 낮추고 히어로 정렬을 바꾼 뒤 질문·결과·탐색에 같은 간격·중립색·컴팩트 컨트롤 원칙을 순서대로 적용하는 것이 효과적이다. 기능 및 복지 정보의 정직성은 유지할 수 있으며, 모바일과 접근성 세부 점수는 다음 라운드에서 실제 캡처·조작 검증으로 보정해야 한다.
