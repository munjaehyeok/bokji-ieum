# R-004 재리뷰 — T1/T2 슬라이스

**T1/T2 보정 슬라이스는 APPROVE.** R-003의 P1 2건·P2 1건은 이번 제출 범위에서 해소된 것으로 판단한다. T0 명세의 사람 확인, T3~T8 완료, 서비스 전체 배포 승인을 뜻하지 않는다.

## 검토 대상과 증거

- 요청서의 대상 28d5b38 이후 현재 HEAD는 `c4a507b0becc2b66224c58e62385fefb7ea243af`다. 추가 커밋은 R-004 요청서이며, 검증 결과가 가리키는 `1bd3dd5`부터 현재 HEAD까지 보정 SQL·검증 스크립트 변경이 없음을 확인했다. 미추적 `pom-verify.xml`은 승인 대상에 포함하지 않았다.
- AGENTS.md·BRIEF·SPEC·PLAN·REVIEW 및 공통 기준, main 대비 변경과 R-003 이후 수정, 근거 CSV·검증 결과·실제 HTTP 컨트롤러 경로를 읽었다.
- 리뷰어 실행: plan-check OK(위험 슬라이스 독립 테스트 경고 1건), 셸 문법 검사 통과, 회귀 Python AST 구문 검사 통과, CSV 16행의 ID·잘못된 날짜·복원 날짜가 SQL과 정확히 일치함을 확인했다. 저장소 파일을 쓰는 컴파일·DB 초기화·앱 실행은 하지 않았다.
- DB 15단언 PASS, 앱 12단언 PASS 및 보정 전 실패 대조, Maven test/package 종료코드 0은 `docs/검증/데이터신뢰도-결과.md`의 **구현자 제출 결과**로 검토했다. 리뷰어가 재실행한 결과와 구분한다. Maven 테스트 클래스는 0개다.

## 이전 지적 처리

1. **P1 복원 SQL 과적용 — 해소.** 16건의 날짜 보정이 알려진 잘못된 날짜와 정확히 같은 상태에만 적용된다. 315 확인일 제거도 특정 기준일·확인일 조합으로 제한됐다. 이후 정상 날짜 3개를 보존하는 회귀 단언과 결과가 제출됐다. 이 보정은 지정 적재 이력에 대한 일회성 데이터 보정이며, 향후 모든 정정 이력을 식별하는 범용 동기화 장치로 확대 해석하지 않는다.
2. **P1 필수 실행 증거 누락 — 해소.** 결과 문서에 대상 커밋·격리 환경·명령·종료코드·데이터 및 앱 단언 출력이 추가됐고 태그 보정 근거 CSV도 분리됐다. Maven 실행 결과와 테스트 0개라는 한계를 명시했다. 비밀 설정을 제외한 검증용 앱 기동 절차는 향후 통합 결과에 재현 가능하게 보완하면 된다.
3. **P2 국적 분할 검사를 앱 불변식으로 취급 — 해소.** 기존 단언은 데이터 분할로 이름을 정정했다. 별도 HTTP 회귀는 세션에 조건을 저장한 뒤 `/match/result/list`로 실제 매칭 경로를 호출한다. 모름 결과 수, 보정 3건의 노출·확인필요, 실제 전체 연령 제한 유지와 고정 스냅샷 수치 검증을 추가했다. 현재 불변식 검사는 결과 개수 비교이며 전체 ID 집합 동등성까지 입증한 것으로 표현하지 않는다.

신규 P0·P1 결함은 확인하지 못했다. 새 브라우저 UI를 구현하지 않은 T1/T2에 대해 미착수 T3/T4 스모크를 이번 승인 조건으로 소급하지 않는다.

## 다음 착수 순서

**T8 → T3/T4 → T5/T7 → T6** 순서로 진행한다. PLAN의 실제 의존도 이 순서를 반영한다. 서로 독립적인 대조 자료 수집은 가능하지만, 공유 매퍼·회귀 파일 수정과 통합은 직렬화한다.

1. **T8:** 180% 등 구간 밖 소득 기준의 rank를 점검·보정하고, rank=NULL·uncertain=Y 전체 행에서 NOTE 또는 전용 태그로 확인필요가 전달되는지 검사한다. 기존 744건의 연령·OR·가구원 조건 위험 후보를 목록화한다. 검증은 별도 테스트 작업으로 PLAN에 적고 match-regression 확장 소유 경로·의존을 명시한다. T2 검증 파일을 수정하는 작업을 무소유 상태로 두지 않는다. 전량 재태깅 완료를 T3 착수 조건으로 만들지 않는다.
2. **T3/T4:** 사업내용 기준과 확인 범위를 초기 렌더·AJAX·상세·4개 언어에 일관되게 표시한다. 목록 존재 확인만 한 자원을 ‘연락처 확인’으로 표시하지 않는다. 날짜 미확인·315 보류 사례와 정렬 설명도 포함한다. 데스크톱·모바일, 콘솔·네트워크, 조건 입력→결과→상세→신청 안내의 스모크를 남긴다.
3. **T5/T7:** 시연 및 긴급·현금·주거, 변경 후보와 실제 오제외 사례부터 본문 대조한다. T7은 구현과 독립적인 대장 수용기준으로 검증한다. 현재 PLAN에는 T7이 본문 테스트로 이미 있으므로 ‘본문 테스트 부재’ 경고가 계속 남았다는 R-004 설명은 현재 파일과 다르다. 실제 plan-check 경고는 위험 슬라이스 1건이다.
4. **T6:** T8과 본문 반영 후 같은 스냅샷에서 수치를 재집계하고 필수 게이트를 통합 실행한다. 현재 47/744는 날짜별 건수이며 ‘본문 검증 완료 건수’로 전환해 발표하지 않는다. BRIEF의 55/737 및 main 동일 커밋 설명은 과거 스냅샷임을 구분하거나 최신 결과로 갱신한다.

T1/T2 재리뷰는 여기서 종료한다. 후속 단계에서 새로 확인된 결함과 통합 검증을 다음 리뷰 대상으로 삼는다.
