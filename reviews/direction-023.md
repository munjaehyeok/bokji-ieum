# Q-023 완성도 향상 실행 계획

작성 기준: 2026-10-22. 본 계획은 Q-023과 R-022의 위험 6개·액션 10개를 저장소 변경, 외부 확인, 사람 판단으로 나눴다. 이 파일은 지시 문서이며 구현·외부 연락·테스트·배포를 대신 수행한 기록이 아니다. 팀 확정인 시흥시 범위, 기존 태깅 원칙, 소득 결정표는 그대로 둔다.

## 사람 전용 체크리스트

### A. 외국인 통계 원문 선택 (T1)

- 제안서에 적힌 72,424명·12.3%의 원자료 파일/URL, 표 제목, 기준일, ‘외국인’ 정의, 분모를 찾는다.
- 사회조사 근거의 40,493명·7.2%는 2024년 총인구 통계라는 점과 원출처를 확인한다.
- 두 값이 등록외국인/외국인주민 등 서로 다른 모집단이면 하나를 오답으로 단정하지 말고 두 정의를 병기하거나 프로젝트 주장을 뒷받침하는 한 값만 사용한다.
- `reviews/source-decision-023.md` 기록: `수치 | 모집단 정의 | 기준일 | 분모 | 원문 출처·페이지 | 선택 이유 | 발표 문구 승인자`.

### B. 복지온·복지로·복지이음 직접 비교 (T2)

- 동일한 합성 시나리오 2개를 사용: (1) 1959년생·시흥 정왕본동·1인가구·수급 입력, (2) 2004년생·시흥 거주·구직·소득 모름. 실제 개인 데이터는 입력하지 않는다.
- 각 서비스에서 로그인 필요 여부, 시흥 민간 자원 확인 가능 여부, 조건 입력, 결과 수/결과 근거, 최신성·출처, 상세 신청 연결, 화면 언어를 확인한다. 없는 기능은 화면에서 확인한 경우에만 ‘없음’; 접근 제한이면 ‘미확인’으로 기록한다.
- 같은 폭(데스크톱 1440px, 모바일 390px)을 사용하고 단계별 URL·날짜·캡처 경로를 적는다. 개인정보·계정·토큰이 캡처에 나오지 않게 한다.
- 기록 열: `서비스 | 날짜/URL | 합성 입력 | 로그인 | 지역/민간 범위 | 결과·설명 | 출처일 | 신청 연결 | 언어 | 캡처 | 미확인`.

### C. 본문 대조 (T8)

- 77건의 사전 고정 목록만 모집단으로 삼는다. 1차는 `긴급` 24건 전부와, 나머지 53건에서 `주거`·`현금성` 사유를 층화해 각 6건(중복 제거) 선정한다. 이는 위험 우선 점검이지 무작위 통계 추정이 아니다.
- 표본 선정 ID와 추출 seed, 실제 strata별 건수를 `body-audit-protocol-023.md`에 먼저 남긴다. 샘플 선택 후 결과를 보고 교체하지 않는다.
- 시흥시 공식 페이지·공식 공고·공식 API 상세 등 원문을 확인한다. 원문이 없으면 전화/공문 답변을 받은 사람이 자료 위치와 일자를 기록; 회신 전에는 ‘미확인’으로 남긴다.
- [대장 형식](../docs/데이터/수집/본문검증대장.csv)의 열을 그대로 사용: `resource_id, 자원명, 확인필드, 전값, 후값, 출처, 출처위치, 확인일, 확인자, 미확인사항`. `확인필드` 허용값은 지원내용·자격·금액·신청방법·서류·기간. 변경 없음은 변경 대장에 넣지 않고 별도 로그에 확인 결과를 남긴다.
- 한 건이라도 폐지/금액/자격 등 중대한 차이가 나오면 같은 자원군의 나머지를 전수확인하고, 이 결과로 77건 전체가 최신이라고 일반화하지 않는다.

### D. 사용성·다국어 검증 (T11·T12)

- T10에서 과제·순서를 동결한 뒤 진행. 계획 9명과 실제 참여 인원을 분리 보고하고, 결원은 추정치로 메우지 않는다.
- 참가자에게 연구 목적·기록 항목을 설명하고 동의를 받는다. 이름·연락처·실제 수급·소득 정보는 저장하지 않는다. 과제에는 위 B의 합성 조건을 쓴다.
- 기록: `익명 코드 | 그룹(어르신/청년/다문화) | 순서 | 서비스 | 과제 성공(기준) | 시간(초) | 클릭 수 | 포기/오류 | 5문항 응답 | 관찰 메모(식별정보 제거)`.
- 요약은 표본 수와 중앙값/범위 및 누락을 표시한다. 30% 시간 단축·평균 4.0은 사전 목표이며 실제 결과가 넘더라도 인과·일반 사용자 효과로 확대해 말하지 않는다.
- 다국어는 화면 UI와 사업 본문 번역을 각각 확인하고, 언어별 참가자의 오해·미번역 영역을 기록한다.

### E. 사람 결정·승인 (T5·T16·T17·T19)

- 관리자 동작 변경은 고정 초기 암호 제거안과 배포 환경에서 계정이 만들어지지 않는 경우의 복구 절차를 검토한 뒤 사람 승인.
- 최신 안내서 요청은 팀원이 담당 부서에 직접 발송하고 회신 내용을 보존. 이 에이전트는 외부 연락을 보내지 않는다.
- 팀원은 실제 기여와 남은 일정을 확인한다. 운영 주체·데이터 공급·갱신 주기·제보 응답 책임은 시 담당부서의 합의를 받은 경우에만 ‘확정’ 표시.
- 공개 배포, 병합, 푸시는 사람의 명시 승인 뒤 사람 또는 승인된 담당자가 수행한다.
