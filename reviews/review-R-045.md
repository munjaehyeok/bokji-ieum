# R-045 · R-044 반영 재검토

**R-044의 P1이 남아 있다.** 열 범위 제한은 도구가 돌려받는 행과 보고서에서 동작한다. `openpyxl` 내부에서는 제외 열의 값을 여전히 해석하며, 담당자 정보를 포함한 원본도 실행 인수로 받을 수 있다. 2025판 seed 교체 보류 판단을 유지한다.

### [P1] `docs/데이터/tools/check_2025.py:3–4,13–17,21` 및 `docs/데이터/수집/검증-2025안내서-20261125.md:7`

**Axis:** Spec  
**Problem:** Q-043의 담당자 값 비열람 조건을 충족하지 못했다. `read_only=True`의 열 경계는 시트 파서가 값을 해석한 다음 반환할 행에 적용된다. 담당자 열 제거 사본은 문서에서 권장하지만 실행 입력에는 그 전제가 적용되지 않는다.  
**Evidence:** `openpyxl` 3.1.5로 AA7·AB7·AC7·AA8에 합성 표식을 넣은 메모리 XLSX를 시험했다. 인라인 문자열과 공유 문자열 두 형식 모두 `WorkSheetParser.parse_cell`과 열을 자르기 직전의 파싱 결과에서 제외 값 4개를 확인했다. 공유 문자열 형식에서는 워크북 로드 시 공유 문자열 테이블에도 표식 4개가 적재됐다. 두 시험에서 `iter_rows`가 내보낸 값에는 표식이 0개였고, 제외 열에만 값이 있는 8행은 집계에 들어가지 않았다. 실제 A/B 원본에 `xl/sharedStrings.xml`이 존재한다는 점은 파일 목록으로만 확인했다. 실제 담당자 값은 시험에 사용하지 않았다.  
**Suggested direction:** 원본 XLSX를 지원하려면 셀 좌표를 먼저 검사해서 허용 열의 값만 해석하고, 공유 문자열도 허용 셀이 참조한 항목만 해석한다. 입력을 담당자 열이 제거된 사본으로 제한하는 경로를 택한다면 이를 사용 조건으로 명시하고, 값을 해석하기 전에 원본의 입력을 차단한다. 합성 표식으로 파서 단계의 제외 값 해석 0건과 집계 유지 여부를 함께 확인한다.  
**Verification:** test, 실제 `openpyxl`과 인라인·공유 문자열을 사용한 메모리 내 XLSX.
