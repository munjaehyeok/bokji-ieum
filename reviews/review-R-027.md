# R-027 탐색 모드 구현 리뷰

## 판정: APPROVE

확인 범위는 R-027 지정 계약·구현·회귀·스모크 보고서와 direction-024 대비 정적 검토다. 제출된 자동 검증 PASS 결과는 보고서에서 확인했으며, 이 읽기 전용 리뷰에서 서버·DB 테스트를 재실행하지 않았다.

## 확인 사항

- **필터·제외 위험:** `ResourceSearch`가 category/life/household/dong 허용값을 제한하고, 기본값은 연령 태그 미분류 자원을 포함한다. `strict=1`만 미분류를 제외한다. LOW는 rank 1·2, `incx=1`일 때만 소득 불확실 자원을 더한다. `FOR`는 `nationality='F'`의 별도 항목이고 MCUL/NKOR 가구 태그와 혼합되지 않는다. 교차 필터·생애주기 구간 겹침·동시 연령 조건은 계약과 SQL이 일치한다.
- **검색:** 사용자 값은 MyBatis 바인딩을 사용하고, LIKE용 `%`, `_`, `\`를 이스케이프한다. 검색어는 AND, 제외어는 각각 NOT 조건으로 결합되어 제외가 우선한다. 값 길이/단어 수와 허용 코드가 제한되며 입력값으로 SQL 조각을 만들지 않는다. 회귀 보고서에는 리터럴 와일드카드와 위험 입력 사례가 포함되어 있다.
- **온라인 신청:** `apply_url`만으로 필터링하지 않고 `apply_method`의 정해 둔 문구만 확인하며, UI는 “온라인 신청 안내가 있는 자원”이라고 표현해 실제 신청 완료를 보장한다고 말하지 않는다. 단, 아래 P2 후속 확인을 권한다.
- **인기순:** 상세 조회 D 이벤트만 사용하고 전체 표본이 30건 미만이면 이름순으로 대체한다. 한국어 안내에 상세 조회 수이며 신청 수·선호도가 아니라는 점도 명시되어 있다.
- **찜·상세:** localStorage를 사용하고 저장 목록을 최대 50개로 제한한다. 요청 ID는 정수·중복 여부를 검사하고 조회 SQL이 활성 자원만 반환한다. 목록 및 상세에서 판정표/기존 비교표를 제거하지 않았고, 조건 없는 상세에서 판정표를 숨기는 기존 동작과 “한눈에 보기/목록으로”가 유지된다.
- **다국어·화면:** 신규 메시지 키는 ko/en/zh/vi 네 파일에 모두 존재한다. 보고된 데스크톱·390px 스모크는 콘솔 0, 예상치 않은 네트워크 오류 0이며, 화면 보고서는 키보드/스크린리더 실사용 및 zh/vi 직접 스모크는 미검증으로 한계를 공개한다.
- **문서와 회귀:** 계약의 미분류 기본 포함, strict, LOW+incx, FOR 분리, 검색 의미, ids 상한, 정렬 fallback과 SQL 구현은 대체로 일치한다. 독립 DB 기대값 회귀와 별도 수동 스모크가 제출됐다. 구현 전후 데이터는 바꾸지 않는 탐색 기능이므로 데이터 게이트는 이번 기능의 직접 변경 범위가 아니다.

## 비차단 후속 권고 (P2)

1. `popularSample()`은 기간 조건 없이 모든 과거 D 이벤트를 세며, 이 전체 건수가 30 이상이면 인기순을 켠다. direction-024의 최근 표본 고려와 달리 오래된 트래픽만으로도 계속 인기순이 활성화될 수 있다. 최근 집계 기간을 계약에 명시하고 쿼리·회귀에도 적용하거나, 기능 의미를 “누적 상세 조회순”으로 고정해 문서에 남기는 편이 낫다.
2. 온라인 신청 정규식은 `복지로`, `정부24`, `e보건소` 단어 자체만 있어도 통과한다. `apply_method`가 신청 채널을 뜻하는 필드라 위험은 제한적이고 화면 문구도 안내로 제한되어 있으나, 해당 단어가 단순 언급된 예외 행이 없는지 샘플 확인을 더하면 오분류를 줄일 수 있다.
3. 목록의 정렬 그룹·페이지네이션 `aria-label`이 각각 고정 영문 `sort`, `pagination`이다. 기존 화면 기능에는 영향이 없지만 네 언어 메시지로 바꾸면 보조기술 사용자에게도 언어별 UI가 일관된다. 스모크 보고서대로 키보드·스크린리더 실사용 검증은 별도로 남아 있다.
