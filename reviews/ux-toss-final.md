# 복지이음 토스식 UX — 최종 합의안

## 목표

복잡한 탐색을 줄이고 사용자가 빠르게 시작하게 한다. 기존 시흥시 자원 범위, 매칭/확인필요 규칙, 4개 언어, 접근성과 자료 기준일 안내를 지킨다. 결과 수 자체를 성공 지표로 삼지 않는다.

## 화면 흐름과 문구

1. **홈:** 주 CTA `내 조건으로 찾기`, 보조 CTA `복지자원 둘러보기`, 작은 선택 링크 `가족 것도 같이 찾기`.
2. **질문:** 한 화면에 한 질문, 큰 입력/선택 카드, 진행 텍스트와 막대, `이전`·`건너뛰기`·`현재 조건으로 결과 보기`. 권장 질문 순서는 나이→동네→가구 상황→소득→장애→국적→학업·취업이다. 순서는 강제 관문이 아니다. 모름을 허용하고 이를 이유로 자원을 제외하지 않는다. 나이 대표값이나 새 매칭 규칙은 만들지 않는다. 가구·소득에는 “왜 묻나요?” 설명과 선택 가능 안내를 둔다. 자동 이동은 기본 OFF, 명시적 `다음`이 기본이다.
3. **결과:** 기존 매칭 분류를 반영해 `입력 조건과 일치하는 자원 M건 · 추가 확인이 필요한 자원 K건`으로 표시한다. M/K의 정의·합계 관계는 T0에서 확정하며 자격 확정으로 표현하지 않는다. 안내 문구 `최종 지원 자격은 담당 기관에 확인해 주세요`를 유지한다. 분야는 자격조건이 아닌 결과 필터다.
4. **결과 카드/상세:** 목록은 제목·요약·일치/확인필요를 우선한다. 확인필요는 텍스트와 아이콘으로 눈에 띄게 표시한다. 기준일·오래된 자료 경고는 목록에서도 유지하고 세부 내용은 상세에서 제공한다. 신청 URL/전화가 있을 때만 해당 CTA를 보여준다. 없으면 `신청 방법 확인(담당 기관 문의)`로 안내한다.
5. **편집·빈 결과:** 조건 편집은 기존 `/match` 재진입을 쓴다. 입력 상태 보존이 없으면 보존만 추가하고 회귀한다. 빈 결과는 필터를 자동 완화하지 않고 사용자가 고르는 완화 칩과 풀릴 조건을 보여준다.

## 구현 슬라이스 및 순서

- **T0 계약·기준선:** 모름, 중간 결과, M/K 분류, 조건 보존의 동작을 명시하고 동일 입력 회귀 사례를 고정한다. 기존 `match-regression.py`와 40개 사례의 결과 ID·라벨을 전후 비교한다.
- **T1 홈 진입:** `index.jsp`, 홈 메시지 리소스, 홈 CSS. 두 CTA와 가족 경로 구현. 4개 언어, 키보드 진입, 390/1280px 스모크.
- **T2 질문 흐름:** `match/form.jsp`, `bokji.js`, `bokji.css`, 메시지 리소스. 단계 안내, 건너뛰기/이전/중간 결과, 민감 질문 설명. 자동 이동은 OFF. 결과 ID·라벨 비교, 4개 언어, AA, 키보드/스크린리더, 확대, 모션 감소 및 핵심 흐름 검증.
- **T3 결과 밀도·편집:** `match/result.jsp` 및 필요한 카드 뷰·JS/CSS/메시지. 카운터, 카드 위계, 기존 편집 경로 상태 보존, 수동 완화. 사용자 테스트 뒤 우선순위 승인 후 진행. 기존 매칭 회귀와 결과 화면 스모크.

경로가 겹치는 슬라이스는 병렬화하지 않고 T0→T1→T2→T3 순으로 통합한다. 구현은 Claude, Codex는 읽기 전용 리뷰, 사람은 명세 및 최종 승인 역할을 맡는다. 신규 SQL·데이터 규칙, 로그인, 서버 개인정보 저장, 지도, 푸시, 챗봇은 범위 밖이다.

## 완료 기준

같은 고정 사례에서 기대 ID·라벨 및 노출 불변식 유지, 모름 입력으로 잘못된 제외 없음, M/K가 기존 분류를 정확히 요약, 4개 언어, AA 대비, 키보드/스크린리더, 모바일 폭, 모션 감소, 핵심 흐름 브라우저 스모크 통과. 사용성 테스트는 완료율·완료시간·중도 이탈·건너뛰기·뒤로 가기·확인필요 이해도를 보고한다. 결과 건수 증가는 단독 성공 지표로 사용하지 않는다.

## 사람 결정 항목

1. 매칭 상태를 자격 확정과 구별하는 카운터 문구와 M/K 정의 승인.
2. 사용성 결과를 보고 단일선택 자동 이동을 켤지 결정(근거 부족 시 출시까지 OFF).
3. 테스트에서 발견한 마찰 중 T3에 포함할 출시 차단 항목의 우선순위 결정.
