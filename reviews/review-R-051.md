# R-051 · 전화번호 분리 최종 재검토

**판정은 REVISE다.** `ca1830b...4674fa1`의 변경을 검토했다. R-050의 직접 재현 사례는 개선됐으나, 실제 자원의 대표 단축번호와 폐기·번역 처리의 후속 반례가 남아 있다.

## 확인 결과

- JUnit 10개가 모두 통과했다. 현재 Java 소스로 저장소 SQL에서 복원한 연락처 878행을 재현했다. 1001은 일반 번호에 링크 2개, 폐기 번호에 링크 0개를 반환했다. 1058·1062·1312의 지역번호 생략 연락처는 다시 연결되고 1563은 3개, 1675는 지역번호 포함 10자리였다. `031-123-45678`과 연속 숫자열의 부분 매치 방지, 같은 줄에서 공백으로 이어진 모호한 라벨의 링크 억제도 확인했다.
- 변경된 번역 순서와 번호 자체가 바뀐 번역은 정상 번호 조각에서 검출된다. 1061·1854처럼 번역의 슬래시 때문에 조각 수가 다른 기존 사례는 원문·번역의 번호가 같으면 전체 번역 안내로 폴백한다. 인쇄용 전체 연락처와 `c:out` 이스케이프도 유지됐다.
- 구현자가 보고한 HTTP 878건 성공은 독립 재실행하지 않았다. 데스크톱·모바일 캡처, 콘솔·네트워크 및 인쇄 미리보기 증거는 `NEEDS_EVIDENCE`다.

### [P1] `src/main/java/com/ieum/bokji/util/TextUtil.java:34–37,91–100`, `src/main/resources/sql/seed.sql:73`

**Axis:** Correctness

**Problem:** 실제 자원에 있는 단축번호가 통화 버튼에서 빠진다.

**Evidence:** 1067 `전기요금 감면`의 연락처는 `123`이다. `ca1830b` 상세는 `tel:123`을 생성하나, 새 함수는 빈 문자열을 반환한다. 878행 중 링크가 없는 3행은 1067(단축번호), 1442(비정형 숫자열), 1854(문자 안내)로 확인됐다. 한전은 유선에서 국번 없이 `123`, 휴대폰에서는 지역번호를 붙인 `123`을 안내한다. [한국전력공사 전기상담 안내](https://www.kepco.co.kr/home/service/errorinquiry/conts.do)

**Suggested direction:** 확인된 서비스 단축번호를 일반 숫자 메모·내선과 구별해 지원하고, 휴대폰에서 필요한 지역번호는 기관 안내에 따라 표시한다. 1067과 문자 안내 1854를 함께 단언한다. 비정형 1442의 번호는 출처 확인 전 글자로 유지할 수 있다.

**Verification:** test/static, 실제 seed와 새 Java 출력 및 이전 JSP 비교.

### [P1] `src/main/java/com/ieum/bokji/util/TextUtil.java:39–40,52–60,91–100`

**Axis:** Correctness

**Problem:** 폐기 라벨과 다음 번호가 줄바꿈으로 구분되면, 라벨은 글자로 분리되고 폐기된 번호가 다시 통화 대상이 된다.

**Evidence:** 합성 입력 `폐기 번호:\n031-123-4567`에서 `splitPhones`는 `폐기 번호:`와 `031-123-4567` 두 조각을 내고 두 번째 조각은 `0311234567`로 연결된다. 쉼표 뒤 줄바꿈에서도 같은 원인으로 상태를 잃는다. 같은 줄의 모호한 라벨과 달리 이 경로에서는 개별 조각만으로 폐기 여부를 판단한다.

**Suggested direction:** 번호가 없는 앞쪽 상태 라벨이 이어지는 번호를 수식하는 입력을 보존한다. 상태가 어느 번호에 적용되는지 모호하면 해당 구간은 글자로 제공한다. 같은 줄, 번호 다음의 `(삭제)`, 폐기 라벨 다음 줄을 각각 검증한다.

**Verification:** test, 현재 Java에서 분리 및 링크 대상 확인.

### [P1] `src/main/java/com/ieum/bokji/util/TextUtil.java:103–145`, `src/main/webapp/WEB-INF/views/resource/detail.jsp:137–156`

**Axis:** Correctness

**Problem:** 번호 목록이 같거나 양쪽 모두 통화 대상이 비어 있으면, 폐기 표시를 누락한 번역과 이미 변경된 번호를 다시 표시할 수 있다.

**Evidence:** 원문 `031-123-4567(삭제)`와 기존 번역 `031-123-4567`에서 `phonesAligned=false`, `sameNumbers=true`다. 상세에는 원문 폐기 표기와 함께 상태 없는 번역을 별도로 표시하며, 인쇄용 전체 연락처는 폐기 표기를 잃는다. 또한 원문 `대야 031-123-4567 정왕 032-234-5678`과 기존 번역 `Daeya 031-999-9999 Jeongwang 032-234-5678`은 각각 모호한 한 조각이다. 양쪽 `telDigits`가 빈 문자열이므로 `phonesAligned=true`가 되고 `firstPhone`도 오래된 번역 전체를 반환한다. 실제 관리자 저장은 원문 `phone`을 바꾸지만 번역을 함께 갱신하지 않으므로 이 상황에 진입할 수 있다.

**Suggested direction:** 번호와 연결 가능 여부를 함께 대조한다. 빈 통화값에는 번호 일치의 의미를 부여하지 않는다. 모호한 조각에 번호가 존재하면 번호 변경도 검출한다. 1001처럼 번역에 실제 폐기 상태가 반영된 경우는 유지하되, 상태나 번호가 바뀐 번역은 상세·목록·인쇄에서 현재 원문으로 폴백한다. `firstPhone`의 기존 테스트는 예상 문자열을 직접 비교하도록 바꿔 빈 값도 통과하는 경우를 막는다.

**Verification:** test/static, `phonesAligned`·`sameNumbers`·`firstPhone`의 Java 반환값과 JSP 분기 및 관리자 저장 경로 대조.
