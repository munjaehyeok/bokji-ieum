# 토스식 UX 의견 교환 — 라운드 3 최종 응답

## 마지막 확인

1. **예.** 남은 blocker는 없다. 제안된 합의를 최종안으로 삼되, 결과 요약의 “조건에 맞는 M건”은 확정 자격으로 오해될 수 있으므로 **“입력 조건과 일치하는 자원 M건 · 추가 확인이 필요한 자원 K건”**처럼 매칭 상태를 설명하는 표현을 권한다. 두 숫자는 기존 분류 결과에서 산출하고, 중복 없이 전체 노출 수와 맞는지 T0에서 정의·검증한다. 자격 최종 확인은 기관 몫이라는 안내도 유지한다.
2. **동의.** 사용성 테스트 전에는 T0·T1·T2를 먼저 완성한다. T3는 테스트 결과를 보고 진행 여부를 정한다. T0 계약을 먼저 고정하고 T1→T2는 순차 통합한다.
3. **동의.** 자동 이동은 기본 OFF로 시작하고 명시적 ‘다음’을 기본 동작으로 둔다. 테스트에서 단일 선택 자동 이동이 완료율을 높이며 오입력·접근성 문제가 늘지 않는 근거가 있을 때만 별도 결정한다.
4. **Claude 구현, Codex 읽기 전용 리뷰를 권고한다.** AGENTS.md의 기본 역할과 일치한다. Codex는 계약 검토와 결과 리뷰를 맡고 구현/수정은 하지 않는다.
5. **사람이 결정할 항목(최대 3개):**
   - 결과 카운터 문구와 M/K 분류가 사용자가 이해하기에 충분한지 승인. 특히 ‘일치’가 자격 확정이 아님을 분명히 할 것.
   - 사용성 테스트 뒤 단일선택 자동 이동을 켤지 결정. 테스트 근거가 부족하면 출시까지 OFF 유지.
   - 테스트에서 확인된 마찰 중 무엇을 T3 출시 전 필수로 올릴지, 나머지는 후속으로 둘지 우선순위 결정.
