# R-050 · R-049 전화번호 분리 재검토

**판정은 REVISE다.** 앞선 괄호·공백 사례와 인쇄용 연락처는 개선됐다. 기존 국번 생략 연락처의 버튼이 사라지고, 공백으로 이어진 번호에 폐기 표시나 번역 라벨이 잘못 연결되는 반례가 남아 있다.

`ca1830b...745298a`를 검토했다. 기존 JUnit을 직접 실행해 6개 모두 통과했다. Java 17에서 현재 소스로 합성 입력과 저장소 SQL에서 복원한 연락처 878행을 실행했다. 1563은 세 번호를, 1675는 지역번호를 포함한 10자리를 반환했다. 1061의 영어·베트남어와 1854의 숫자 없는 번역은 조각 수 불일치 시 전체 번역 문구를 남기는 경로에 들어간다. 인쇄 CSS와 새 `d-print-block` 전체 연락처를 확인했다. 구현자가 보고한 상세 HTTP 878건 성공을 독립 재실행하지 않았다. 데스크톱·모바일 화면, 콘솔·네트워크 및 인쇄 미리보기는 `NEEDS_EVIDENCE`다.

### [P1] `src/main/java/com/ieum/bokji/util/TextUtil.java:32–35,79–84`

**Axis:** Correctness

**Problem:** 새 정규식은 기존 국번 생략 연락처의 통화 기능을 없애고, 반대로 더 긴 숫자열의 일부를 전화번호로 허용한다.

**Evidence:** 실제 활성 ID 1058·1062·1312의 연락처는 각각 `DDD-DDDD` 단일 값이다. 이전 화면에서는 해당 값으로 통화 링크를 만들었으나 현재 함수는 모두 빈 `tel`을 반환한다. ID 1001도 앞 두 일반 연락처를 포함해 링크가 0개다. 1001의 폐기 번호에 링크가 없다는 결과만으로 일반 번호의 통화 기능 보존은 검증되지 않는다. 합성 입력 `031-123-45678`에서는 마지막 자리를 버린 `0311234567`을 반환하며, `참조번호 003112345678999, 031-234-5678`에서는 첫 숫자열 일부를 별도 통화 대상으로 생성한다.

**Suggested direction:** 기존의 지역번호 생략 형식을 연락처 토큰으로 구분하고 기존 통화 경로를 보존한다. 전체 번호가 필요한 환경에서는 검증된 지역번호를 데이터에 보완한다. 연속 숫자나 긴 토큰 내부의 일부 매치는 거부한다. 1001의 일반 번호와 폐기 번호를 같은 회귀에서 함께 확인한다.

**Verification:** test, Java 17과 SQL에서 복원한 현재 번호 형식.

### [P1] `src/main/java/com/ieum/bokji/util/TextUtil.java:59–73,79–84`

**Axis:** Correctness

**Problem:** 공백으로 이어진 번호의 앞쪽 라벨을 이전 번호에 붙인다. 폐기 표시가 다음 번호의 라벨일 때 활성·폐기 상태가 뒤바뀐다.

**Evidence:** Java에서 `대야점 031-123-4567 정왕점 032-234-5678`은 `[대야점 031-123-4567 정왕점, 032-234-5678]`로 분리됐다. `대야점 031-123-4567 폐기 번호: 032-234-5678`은 첫 조각에 `폐기 번호:`가 붙어 첫 링크가 없어지고, 두 번째 폐기 번호로 통화 링크가 생성됐다. 공백만으로 번호를 구분하는 입력은 이번 수정이 명시적으로 지원하는 형식이다.

**Suggested direction:** 명확한 앞쪽 지점·상태 라벨이 해당 번호와 함께 남도록 경계를 잡는다. 상태를 어느 번호에 적용할지 불확실한 경우에는 통화 동작을 붙이기 전에 원문 관계를 보존한다. 순수 번호만 공백으로 이어진 사례와 앞쪽 폐기 라벨을 각각 검증한다.

**Verification:** test, 현재 Java 분리 결과와 `telDigits` 결과.

### [P1] `src/main/webapp/WEB-INF/views/resource/detail.jsp:134–156`, `src/main/webapp/WEB-INF/views/resource/list.jsp:94`

**Axis:** Correctness

**Problem:** 번역과 원문의 조각 수가 같다는 조건만으로 순서대로 연결한다. 화면에 보인 번호와 실제 링크가 달라질 수 있다.

**Evidence:** 합성 입력에서 원문 순서를 `대야점 031-123-4567, 정왕점 032-234-5678`, 번역을 `Jeongwang 032-234-5678, Daeya 031-123-4567`로 두면 양쪽 수는 2로 같고 첫 라벨은 정왕점인데 실제 통화는 대야점으로 연결된다. 현행 SQL에서 복원한 12개 자원·언어 조합의 통화 번호 순서는 일치했다. 다만 관리자 수정 경로는 `resource.phone`을 변경하고 번역을 함께 갱신하지 않는다(`AdminService.java:32–37`, `resource-mapper.xml:218–223,338–355`). 예를 들어 두 번째 원문 번호만 바꿔도 기존 번역의 두 번째 번호가 버튼에 보이고 링크는 새 번호로 연결된다. 카드와 인쇄의 번역 표시에도 같은 오래된 값이 남을 수 있다.

**Suggested direction:** 표시 라벨과 통화 대상을 정규화 번호로 검증하고, 불일치하면 현재 원문의 번호와 확인 가능한 텍스트를 사용한다. 숫자 없는 번역 안내는 유지한다. 같은 조각 수의 순서 변경, 원문 번호 수정, 현행 1061·1854의 폴백을 검증한다.

**Verification:** test/static, Java 분리, JSP 인덱스 매핑 및 실제 관리자 저장 경로 확인.

전화 표시값은 `c:out`으로 이스케이프되고 `href`의 동적 값은 숫자 및 선행 `+`로 제한된다. 변경 범위에서 HTML 속성 오염은 확인되지 않았다.
