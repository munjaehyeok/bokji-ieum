# R-049 · 전화번호 분리 검토

**판정은 REVISE다.** 신고된 ID 1563의 연락처는 세 개의 통화 대상으로 분리됐다. 지역번호가 잘리는 형식, 폐기 표시된 번호로 통화할 수 있는 문제, 연락처 번역 손실이 남았다.

`main...HEAD`의 변경 범위를 확인했다. 로컬 `main`은 `80cca89`로 이전 병합도 포함한다. `origin/main`과 `156b75e`의 부모는 모두 `ca1830b`이므로 전화번호 변경 6개 파일은 `ca1830b...156b75e`로 판정했다. 기존 JUnit 4개를 직접 실행해 모두 통과했고, 현재 Java 소스로 합성 입력과 SQL에서 복원한 연락처 878행을 확인했다. MySQL과 브라우저는 재실행하지 않았다. 이 브랜치의 데스크톱·모바일 스모크 증거는 확인되지 않았다(`NEEDS_EVIDENCE`).

### [P1] `src/main/java/com/ieum/bokji/util/TextUtil.java:32–34,58–64`

**Axis:** Correctness  
**Problem:** 분리와 링크 생성 정규식이 같은 번호 안의 서식과 번호 사이의 경계를 혼동한다. 지역번호 일부가 빠지거나 여러 번호가 한 통화 대상으로 합쳐질 수 있다.  
**Evidence:** 제출된 함수를 Java 17에서 실행했다. `031 123 4567`과 `+82 31 123 4567`은 정상적으로 유지됐다. 아래 반례는 실패했다.

| 합성 입력 | 실제 링크 대상 |
|---|---|
| `(031)123-4567` | `1234567` |
| `031  123 4567` | `031`은 링크 없이 표시되고 `1234567`로 연결 |
| `031 123 4567 032 234 5678` | `03112345670322345678` 한 개 |
| `031-123-4567 1588-0000` | `031123456715880000` 한 개 |
| `(2026-11-27 기준)031-123-4567` | `20261127` |

실제 ID 1675는 `DDD)DDD-DDDD` 형태다. 새 함수는 10자리 중 마지막 7자리만 `tel` 링크에 넣는다.  
**Suggested direction:** 괄호·공백·하이픈을 허용한 완전한 전화번호를 먼저 식별한다. 번호 사이와 표기 내부의 공백을 구별하고 대표번호도 이어진 다음 번호로 인식한다. 라벨의 날짜·지점번호는 통화 대상에서 제외한다. 줄임 번호의 표기는 보존하고, 외부 통화 대상을 추정할 수 없으면 글자로 표시한다. 위 입력과 실제 ID 1675의 지역번호 보존을 회귀로 추가한다.  
**Verification:** test, 현재 Java 메서드 소스와 실제 SQL 연락처 형식.

### [P1] `src/main/webapp/WEB-INF/views/resource/detail.jsp:134–145`

**Axis:** Correctness  
**Problem:** 폐기 표시가 붙은 번호에도 `전화 걸기` 버튼을 추가한다.  
**Evidence:** 실제 ID 1001 연락처의 세 번째 조각은 `DDD-DDDD(삭제)`다. 기존 상세 화면의 통화 버튼은 첫 번호에만 연결됐고, 변경 후에는 해당 폐기 번호에도 숫자 링크가 생성된다. 삭제 표시는 번역 원문에도 보존돼 있다.  
**Suggested direction:** 입력의 명시적인 삭제·폐기 상태를 보존해 통화 가능한 연락처에서 제외한다. 원문 표기가 필요하면 글자로 제공한다. 해당 자원의 앞 두 연락처와 폐기된 세 번째 연락처를 구분하는 회귀를 추가한다.  
**Verification:** test/static, 실제 저장값의 상태 문구와 Java 출력, 이전·현재 JSP 비교.

### [P1] `src/main/webapp/WEB-INF/views/resource/detail.jsp:23,134–144`, `src/main/webapp/WEB-INF/views/resource/list.jsp:94`

**Axis:** Correctness  
**Problem:** 상세 담당 기관의 연락처를 한국어 원문으로만 표시해 이용자의 언어로 제공하던 연락처 안내와 지점 구분을 잃는다. 카드의 번역 조각과 상세 화면의 원문 조각 수도 일치하지 않는다.  
**Evidence:** 번역 SQL의 이름·연락처 해시 조인을 재현했을 때 연락처 번역이 있는 자원·언어 조합 12개 중 4개에서 분리 조각 수가 달랐다. ID 1061은 한국어 두 조각, 영어·베트남어는 괄호 안 `City/county`와 `thành phố/quận` 때문에 세 조각이다. 통화 대상 자체는 두 개로 일치하지만 번호 순서대로 조각을 대응시키면 두 번째 라벨이 끊긴다. 현재 담당 기관 블록은 광역·시군 센터 라벨을 한국어로만 표시한다. ID 1854의 ‘각 시군 노인복지과’도 이전에는 현지어 안내가 표시됐으나 새 상세 본문에는 한국어만 나온다.  
**Suggested direction:** 통화 대상은 원문 번호에서 구하고 표시 라벨은 번역에서 유지한다. 번호별로 대응할 때는 정규화한 번호를 기준으로 검증하고, 라벨 안 구분자와 숫자 없는 안내는 원문 의미가 보존되도록 처리한다. 대응이 불가능할 때는 번역된 안내를 별도 텍스트로 남긴다. 두 ID로 다국어 회귀를 추가한다.  
**Verification:** test/static, 번역 사전과 JSP의 원문·번역 사용 경로 대조.

### [P2] `src/main/webapp/WEB-INF/views/resource/detail.jsp:23,134–145`, `src/main/webapp/static/css/bokji.css:131–132`

**Axis:** Correctness  
**Problem:** 기존 상세 인쇄에서는 전체 연락처가 남았으나 새 화면의 추가 번호는 인쇄에서 사라진다.  
**Evidence:** 이전 담당 기관 블록은 전체 연락처의 텍스트와 인쇄에서 숨기는 통화 버튼을 따로 두었다. 변경 후에는 통화 가능한 번호가 모두 `bk-noprint` 링크에만 들어가며 인쇄용 CSS가 이를 숨긴다. 상세 상단 카드에 남는 연락처는 첫 조각이므로 ID 1563의 두 번째와 세 번째 번호는 인쇄본에서 빠진다.  
**Suggested direction:** 통화 버튼과 함께 인쇄에서 볼 수 있는 전체 연락처 텍스트를 유지하고 인쇄 미리보기에서 다중 번호를 확인한다.  
**Verification:** static, JSP·인쇄 CSS 대조. 브라우저 인쇄 미리보기 `NEEDS_EVIDENCE`.

전화 라벨은 변경된 JSP의 상세·목록에서 `c:out`을 거친다. 상세 `href`의 동적 부분은 `bk:tel`이 생성하는 숫자 및 선행 `+`로 제한된다. 변경 범위에서 HTML 속성 오염이나 XSS 경로는 확인되지 않았다. 위 링크 지적은 번호의 의미와 정확도에 관한 것이다.
