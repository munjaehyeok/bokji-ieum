### [P1] `docs/데이터/tools/build_2025.sh:2–25`

**Axis:** Correctness  
**Problem:** 새 재생성 경로가 MySQL 실패를 성공으로 바꾸고, 2022판 대신 이동하는 `origin/main`을 기본 원본으로 사용한다. 실패한 중간 생성물이나 다른 기준판이 결과 파일에 반영될 수 있다.  
**Evidence:** 7행의 래퍼에 종료 코드 1과 합성 SQL 오류를 반환하는 `docker`를 넣자 래퍼의 종료 코드는 0이었다. 11–19행의 DB 생성·적재·조회에도 같은 래퍼가 사용된다. 또한 임시 폴더가 비어 있고 변경이 main에 병합된 뒤 기본값으로 실행하면 2025판 자원과 패치를 `orig`에 저장한다. 이관 도구의 `OLD_BASE=744`는 2022판을 전제로 한다. 24–25행은 전체 적재·검증을 완료하기 전에 저장소의 SQL을 덮어쓴다.  
**Suggested direction:** SQL 실행의 실패 코드를 보존하고 오류는 표준오류로 유지한다. 2022판 커밋을 고정하거나 필수 인수로 받아 이름·ID 대역·건수를 확인한다. SQL과 CSV를 작업 디렉터리에서 생성해 빈 DB 적재와 게이트를 통과한 뒤에만 교체한다. 사람 결정 권고는 수정이다. 향후 사용을 수용 범위에서 제외한다면 현재 파이프라인을 재생성 절차로 배포하지 않는 방안을 검토한다.  
**Verification:** test/static, DB를 호출하지 않고 합성 오류의 종료 코드와 원본 선택 로직을 확인했다.

**Problem:** 공개 산출물의 마스킹은 개선됐으나 원본을 바로 입력하면 담당자 값의 해석을 막지 못한다.

**Verification:** test, `openpyxl` 합성 표식 및 생성 SQL의 형식 검사.
