## 결론과 선택지 (사람 결정 필요)

seed는 **교체하지 않았다**(교체 요건 "문제없음" 미충족). Codex 검토(R-043)도 동의: 보류 + 검증 문서·도구만 PR.

1. **추가 병합(권장)**: 현행 7단계 적재 뒤 별도 멱등 SQL로, 기존 792건의 id·번역·참조를 보존한 채 (a) 동일성이 확인된 자원은 근거를 남겨 본문 갱신, (b) 확인된 신규 자원만 추가. 신규 행은 안정적인 대응 키를 두어 재실행 시 중복을 막고, `기존 id ↔ 원본 행` 대응표·판정 근거 CSV를 `docs/데이터/수집/`에 둔다. 기존 안내서에만 남은 자원은 담당부서의 종료·개편 근거가 확인된 경우에만 별도 조치하고, 새 자료가 있다고 기준일을 일괄 상향하지 않는다. 적재 후 빈 DB 전체 적재 + 새 SQL 2회 적용, 불변식(`'전 필드 모름' 노출 = 활성 전체 − F전용`), 실제 매칭 노출, 문서·발표 수치를 재확인.
2. **전량 교체**: A 854건을 새 seed로. id 패치·번역·분류 체계·문서 숫자를 전부 재작업해야 하며 발표 일정상 위험.
3. **보류**: 데이터 유지, 복지정책과에 사업 종료·개편 여부 확인 후 결정.

### Codex R-047·R-048 후속 (재검토 한도 도달 — 남은 사항은 사람 결정)

반영: 가족·조부모·예외·대상자 열거·진학 희망 문구 완화(대표 반례를 `match-regression.py`로 고정), 결혼이민자 단독 F 근거 폐지(F 7건), 과거 연도 안내 문구는 '응시·신청·모집' 문맥에만, 상세 화면에서 조건 입력 없이도 '추가 조건' 안내 표시(`detail.jsp`), 시설 확인일은 확인 전화 일치 시에만, 재생성 스크립트 `tools/build_2025.sh`(OLD_REF 필수·종료 코드 보존·담당자 열 있는 입력은 `ALLOW_PERSONAL_COLUMNS=1` 요구).

사람 결정이 필요한 한계(R-048 P1에서 수정·수용을 구분하지 못한 것):
1. 담당자 열이 든 원본 xlsx를 변환하면 openpyxl 내부 파싱에서 해당 열이 해석된다(행 데이터·산출물에는 없음). 담당자 열을 제거한 사본을 쓰면 해소된다.

3. 출생축하금(1233·1873)의 실제 대상·금액 차이와 1602의 현재 접수 여부, 2022판 531행의 종료·개편 판정은 담당부서 확인 전까지 '확인 필요'로만 표시된다.
