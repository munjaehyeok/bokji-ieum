# 06. 에이전트 팀 운영 계획

> 상태: **대기** — 에이전트 정의만 완료(`.claude/agents/`), 실행은 "시작" 지시 후.

## 1. 로스터 (6개)

| 에이전트 | 역할 | 입력 | 산출물 |
|---|---|---|---|
| `data-collector` | 자료수집 | 설계서 00·02, 웹 | `데이터/수집/` (자원후보.csv, 행정동, 중위소득표, API 명세, 수집로그) |
| `data-engineer` | DB·태깅 | 수집 산출물, 설계서 02·03 | `schema.sql`, `seed.sql`, 태깅-현황.md |
| `backend-dev` | Spring·매칭 엔진 | schema 확정본, 설계서 01·03·04 | 동작하는 서버 (매칭 SQL, 전 URL, 관리자) |
| `frontend-dev` | JSP·다국어·접근성 | 백엔드 URL·모델, 설계서 04 | 화면 8종, messages 4개 언어 |
| `qa-verifier` | 검증 | 설계서 03 결정표·05 시나리오 | match_test, 검증표.md, 발표숫자.md |
| `design-reviewer` | 게이트 리뷰 (읽기 전용) | 설계서 전체 | 통과/반려 판정 |

오케스트레이션은 메인 세션(나)이 담당: 단계 전환, 게이트 호출, 병렬 투입 판단, 사용자 보고.

## 2. 데모 빌드 파이프라인 (시작 지시 시 이 순서로)

```
P0 환경 점검(메인): Java·Maven·MySQL(또는 Docker) 확인, 원본 엑셀 유무 확인
P1 data-collector ──────────────┐
   (원본 있으면 보완만, 없으면    │ 병렬 가능: backend-dev가 P1과 동시에
    데모 시드 60건+ 수집)        │ 프로젝트 골격(P2a)을 먼저 시작
P2a backend-dev: 골격·설정      │
P2b data-engineer: schema+태깅+seed  ← P1 산출물
     ▶ GATE 1: design-reviewer (스키마·태깅이 설계서 02·03에 맞는가)
P3  backend-dev: 매칭 SQL·컨트롤러·관리자   ∥  qa-verifier: 결정표 기대값 선작성
     ▶ GATE 2: 결정표 30케이스 통과 + reviewer 리뷰
P4  frontend-dev: 화면·다국어·접근성
P5  qa-verifier: 시나리오 S1~S6 + 통합 + 발표숫자
     ▶ GATE 3: 6개 중 5개 통과 + reviewer 최종 리뷰
P6  메인: 로컬 데모 기동 확인, 데모 시연 경로 문서(데모/README.md), 사용자 보고
```

규칙: 게이트 반려 시 해당 단계 에이전트에 결함 목록을 그대로 전달해 수정 → 재리뷰. 가중치 조정으로 테스트를 무마하는 수정은 금지(결정표가 진실의 원천).

## 3. 데모 범위 (필수 M1~M6 = 제안서 그대로)

- 포함: 비회원 7스텝 입력 → 매칭(일치/확인필요 태그) → 상세+신청 안내 → 다국어 4종 → 관리자 등록·수정·숨김 → 오류 제보
- 데모에서 제외(실서비스 단계로 이월): 배포(EC2), 복지로 API 배치(명세 확보까지만), 회원·알림·지도
- 데이터: 원본 744건 확보 전이면 수집 시드 60건+로 데모 — **단, S1~S6을 전부 만족시키는 구성일 것**

## 4. 시작 전 결정 필요 (사용자 확인)

| # | 질문 | 상태 / 기본값 |
|---|---|---|
| 1 | 종합안내서 원본 | ✅ **해결(10/13)** — `참고자료/…/시흥시 복지자원 종합안내서.xlsx`, 744건·22열 구조 확인. 데모도 전량 744건으로 진행 |
| 2 | Spring 방식 | ✅ **결정(10/13): 비-Boot Spring MVC(web.xml) + 외장 Tomcat — 수업 실습과 동일 구조 원칙.** 기동은 `./mvnw cargo:run`(Tomcat 자동)으로 해결. 예외: 수업 실습이 Boot면 Boot로 전환(사용자 확인 대기, 기본값 비-Boot) |
| 3 | DB | ✅ **결정(10/13): DB는 공유하지 않고 재현** — repo에 docker-compose.yml(mysql:8)+schema.sql+seed.sql+SETUP.md. 이 Mac은 Docker 보유 확인. 공유 DB는 8주차 배포 서버에서만 |
| 4 | 환경 | 이 Mac: Java 17 ✅ · Docker ✅ · Maven ❌(P0에서 `brew install maven` 후 wrapper 생성, 이후 팀원은 mvnw만 사용) |

## 4.5 최종 제출물 형식 (과거 CE 결과물에서 확인, 2024~2025 웹서비스 기준)

팀별 제출 구성: 최종 발표자료(pptx+pdf) · 결과 보고서(pdf) · **소스코드 zip** · 데모/발표 영상(mp4) · **환경설정 txt + DB 설명 txt**(테이블 정의 서술). → 우리는 환경설정·DB 설명을 설계서 01·02에서 자동 추출하면 되고, 과거작 대비 차별점은 실 URL 배포 + 검증 수치임을 발표에서 명시.

## 5. 사람(팀원) ↔ 에이전트 역할 대응

에이전트 산출물은 각 팀원의 담당 영역 초안이다. 최종 제출물은 팀원이 이해·수정할 수 있어야 하므로, 각 단계 보고에 "담당 팀원이 읽어야 할 파일" 목록을 포함한다: data-* → 문재혁 / backend → 이병화 / frontend → 김재민·이윤재 / qa → 이윤재.
