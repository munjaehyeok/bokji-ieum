# 02. 데이터베이스 설계

## 1. ERD (개체 관계)

```
                    ┌────────────────┐
                    │    RESOURCE    │ 744건 (자원 + 자격조건 + 신청정보)
                    └───┬────┬───┬───┘
        1:N ┌───────────┘    │   └───────────┐ 1:N
┌───────────▼───┐   ┌────────▼──────┐   ┌────▼─────────┐
│ RESOURCE_I18N │   │    REPORT     │   │ RESOURCE_    │
│ (다국어, 권장) │   │  (오류 제보)   │   │ HISTORY      │
└───────────────┘   └───────────────┘   │ (변경 이력)   │
                                        └────▲─────────┘
┌──────────┐  처리/수정                       │
│  ADMIN   │─────────────────────────────────┘
└──────────┘
┌───────────┐ 1:N ┌──────────┐      ┌───────────┐  ┌───────┐
│  MEMBER   │─────│ FAVORITE │──N:1→│ RESOURCE  │  │ NEWS  │ (권장, 독립)
│ (선택)    │     └──────────┘      └───────────┘  └───────┘
└───────────┘
┌───────────┐     ┌───────────┐
│ MATCH_LOG │     │ EVENT_LOG │   익명 로그 2종 (FK 없음, 집계 전용)
└───────────┘     └───────────┘
```

원칙: 자격조건을 별도 테이블로 빼지 않는다(744건·조건 7종 고정 → RESOURCE 컬럼이 가장 단순하고 매칭 SQL도 단일 테이블 스캔으로 끝남).

## 2. 테이블 정의서

### RESOURCE — 복지자원 (핵심)

| 컬럼 | 타입 | NULL | 설명 |
|---|---|---|---|
| resource_id | INT AUTO_INCREMENT PK | N | |
| name | VARCHAR(200) | N | 자원명 |
| category | VARCHAR(20) | N | 분야 코드 — 원본 9대분류 그대로: JOB(일자리), HOUSE(주거), DAILY(일상생활), HEALTH(신체건강·보건의료), MIND(정신건강·심리정서), CARE(보호·돌봄·요양), EDU(보육·교육), CULTURE(문화·여가), RIGHTS(안전·권익보장) |
| provider_type | CHAR(3) | N | PUB(공공 200건) / PRV(민간 544건) |
| org_name | VARCHAR(100) | N | 제공 기관명 |
| dept_name | VARCHAR(100) | Y | 담당 부서 |
| phone | VARCHAR(150) | Y | 연락처 — 원본에 복수 연락처 병기 셀이 있어 150으로 확장(2026-10-13). 화면에서 첫 번째 번호만 `tel:` 링크화 |
| address | VARCHAR(200) | Y | 기관 주소 |
| support_content | TEXT | N | 지원 내용 |
| apply_method | TEXT | Y | 신청 방법 (NULL → 화면에 '담당기관 문의' 표시) |
| documents | TEXT | Y | 준비 서류 (NULL → '담당기관 문의') |
| apply_url | VARCHAR(300) | Y | 온라인 신청/안내 URL |
| **-- 자격조건 (태깅 7필드, NULL = 해당 조건 무관) --** | | | |
| age_min / age_max | SMALLINT | Y | 만 나이 하한/상한 |
| dong_codes | VARCHAR(200) | Y | 행정동 코드 CSV (예: `JWB,JW1`). NULL=시 전체 |
| household_types | VARCHAR(100) | Y | 가구형태 CSV: ONE(1인), SPAR(한부모·조손), MCHD(다자녀), MCUL(다문화), NKOR(북한이탈), PREG(임신·출산) |
| income_rank | TINYINT | Y | 소득 상한 랭크: 1=수급만, 2=차상위까지, 3=중위100%까지, 4=중위150%까지 |
| income_uncertain | CHAR(1) | Y | 'Y' = 중위 50~99% 등 세부 기준 존재 → 일치여도 '확인 필요' 병기 |
| disability | CHAR(1) | Y | 'Y' = 장애인 대상 |
| nationality | CHAR(1) | Y | 'F' = 외국인 대상/전용(약 71건), 'K' = 주민등록 내국인 한정 |
| edu_work | VARCHAR(50) | Y | CSV: STU(초중고 재학), UNIV(대학·학업), SEEK(구직·취준), WORK(재직) |
| uncertain_note | VARCHAR(300) | Y | 구조화 못 한 서술형 조건 → 항상 '확인 필요'로 노출 (예: "국가유공자 우선") |
| **-- 출처·관리 --** | | | |
| source_name | VARCHAR(100) | N | 기본: '시흥시 복지자원 종합안내서' |
| source_url | VARCHAR(300) | Y | 원문/사업안내 PDF 링크 |
| data_base_date | DATE | N | 자료 기준일 (12개월 경과 시 화면에 '확인 필요' 뱃지) |
| last_verified_date | DATE | Y | 최근 검증일 (복지로 API 대조 또는 수동) |
| status | CHAR(1) | N | A=노출, H=숨김, E=종료 (물리 삭제 금지) |
| created_at / updated_at | DATETIME | N | |

인덱스: `idx_status_category(status, category)` — 매칭은 풀스캔(744건)이라 그 외 불필요.

**테이블명 표기 확정(2026-10-13, GATE 1 지적 반영)**: 모든 테이블명은 **소문자**(resource, resource_i18n, admin_user, report, resource_history, match_log, event_log, news, member, favorite)로 통일한다. 리눅스 MySQL은 lower_case_table_names=0(대소문자 구분)이 기본이라 혼용 시 배포에서 깨진다. ※ ADMIN은 예약어 충돌 여지가 있어 `admin_user`로 명명.

### RESOURCE_I18N (권장) — 외국인 대상 71건 우선 번역

| 컬럼 | 타입 | 설명 |
|---|---|---|
| resource_id + lang | PK(복합) | lang: en/zh/vi |
| name_tr | VARCHAR(200) | 번역 자원명 |
| summary_tr | VARCHAR(500) | 번역 요약(지원내용 1~2문장) |

조회 시 LEFT JOIN, 없으면 한국어 폴백. 번역 범위는 요약까지만(전문 번역은 제외 범위).

### ADMIN / REPORT / RESOURCE_HISTORY

```sql
ADMIN(admin_id PK, login_id UNIQUE, pw_hash CHAR(60), name, created_at)
REPORT(report_id PK, resource_id FK, content VARCHAR(500),
       status CHAR(1): R접수/C확인/D반영/X반려, admin_memo, created_at, processed_at)
RESOURCE_HISTORY(history_id PK, resource_id, admin_id, action CHAR(1): C/U/H/E,
       changed_summary VARCHAR(500), created_at)   -- 변경 전후 요약 텍스트로 충분
```

### MATCH_LOG / EVENT_LOG — 익명, FK 없음 (05 검증 지표의 원천)

```sql
MATCH_LOG(log_id PK, session_hash CHAR(32), age_band VARCHAR(10),  -- '60s'
          dong VARCHAR(10), household_types, income_rank, disability,
          nationality, edu_work, result_count INT, created_at)
EVENT_LOG(log_id PK, session_hash CHAR(32),
          event CHAR(1): M매칭/D상세조회/A신청안내확인/R제보,
          resource_id INT NULL, created_at)
```

### MEMBER / FAVORITE (선택) · NEWS (권장)

```sql
MEMBER(member_id PK, email UNIQUE, pw_hash CHAR(60), lang CHAR(2), created_at)
FAVORITE(member_id + resource_id PK, created_at)
NEWS(news_id PK, title, url UNIQUE, source, keyword, published_at, collected_at)
```

## 3. 코드 정의 (Java enum + messages.properties로 관리, 코드 테이블 없음)

- **행정동**: 대야(DY), 신천(SC), 신현(SH), 은행(EH), 매화(MH), 목감(MG), 군자(GJ), 월곶(WG), 과림(GL), 연성(YS), 장곡(JG), 능곡(NG), 배곧1(BG1), 배곧2(BG2), 정왕본(JWB), 정왕1~4(JW1~4) ※ **거모동 신설 여부 포함, 시흥시 누리집 기준으로 3주차에 최종 확정**
- 소득 랭크(사용자 입력): 1 기초생활수급 / 2 차상위 / 3 기준중위소득 100% 이하 / 4 그 이상 / 0 모름 — 화면에는 "월소득 ○○만원 이하" 2026년 기준금액을 병기해 선택을 돕는다(가구원수별 표 팝업).

## 3.5 원본 확보 확인 (2026-10-13) — 종합안내서 실제 구조

원본: `참고자료/2026년 시흥시 주요 현안 자료/4. 시흥시 사회복지 정책자료/시흥시 복지자원 종합안내서.xlsx`
구조: 시트 10개 = 표준분류체계 1 + **분야별 데이터 시트 9개, 각 헤더 3행, 22열, 합계 정확히 744건**
(일자리 60 · 주거 33 · 일상생활 81 · 신체건강 67 · 정신건강 73 · 보호돌봄 58 · 보육교육 172 · 문화여가 179 · 안전권익 21)

| 6 서비스명 / 7 상세내용 | | name / support_content |
| 8 지원대상자 대분류 | 공통·노인·아동·한부모… | 태깅 1차 힌트 (household/age/disability) |

설계 영향: 당초 가정보다 좋음 — 지역(15)·신청방법(17)·서류(18)·부담금(19)이 **명시 열로 존재**해 태깅 공수가 줄어든다. 수작업 태깅의 본체는 9열(지원 기준) → 7필드 변환 하나로 수렴. 병합 셀(헤더 3행)과 줄바꿈 포함 셀만 파서에서 처리하면 된다.

적재 후 확정 사항 (2026-10-13, 744건 적재·검증 완료):
- **source_url**: 원본 엑셀에 행 단위 URL이 없어 전 행 NULL — 출처는 source_name+data_base_date로 보장하고, URL은 관리자 화면에서 수시 보강하는 운영 항목으로 변경.
- **성별 조건(여성 전용 등)**: 7필드에 코드가 없어 uncertain_note(확인필요) 처리로 확정 — 데모 범위의 알려진 한계로 기록, 필드 추가는 이관 후 개선 과제.
- 실측: PUB 198 / PRV 546(제안서 '공공 200'과 4건 차이 — 원문 '공공/민간'·'지역발굴' 표기 4건의 매핑 차이), 무료(cost_flag=X) 530건 = 71.2%(제안서 '약 71%' 일치), nationality='F' 21건(제안서 '약 71건'은 다문화 포함 집계로 추정 — **발표 수치 사용 시 주의**).

## 4. 태깅 스키마 — 서술형 자격조건 → 필드 변환 규칙

작업 방식: 종합안내서 엑셀 → POI 1회 변환으로 구글시트 적재(컬럼 = RESOURCE 테이블과 1:1) → **4인 분담 수작업 태깅**(C 주관) → CSV export → `LOAD DATA`. 진행률·담당·검수 컬럼을 시트에 둔다.

대표 변환 규칙 (태깅 가이드로 시트 1번 탭에 고정):

| 원문 예 | 태깅 |
|---|---|
| "만 65세 이상 어르신" | age_min=65 |
| "청소년(9~24세)" | age_min=9, age_max=24 ※ 연 나이 표기면 그대로, 판정에서 ±1 관용(03 문서) |
| "기초생활수급자 및 차상위계층" | income_rank=2 |
| "기준중위소득 75% 이하" | income_rank=3, income_uncertain=Y |
| "저소득층" (기준 불명) | income_rank=3, income_uncertain=Y, uncertain_note="소득기준 상세 문의" |
| "정왕동 거주" | dong_codes=JWB,JW1,JW2,JW3,JW4 (법정동→행정동 전체 포함) |
| "관내 거주" / 명시 없음 | dong_codes=NULL |
| "결혼이민자", "외국인주민" | nationality=F, household_types에 MCUL 추가 검토 |
| "주민등록을 둔 시민" | nationality=K |
| "한부모가족지원법상 보호대상" | household_types=SPAR, income_uncertain=Y |
| "장애인복지카드 소지자" | disability=Y |
| 판단 불가 서술 | 필드 비우고 uncertain_note에 원문 요약 — **임의 해석 금지** |

품질 규칙: ① 태깅자 ≠ 검수자(교차 검수) ② 1주 분량 샘플 50건으로 규칙 보완 후 전체 진행 ③ 완료율·불명 건수를 시트에 집계(발표 때 "744건 중 N건 구조화, M건 확인필요 처리" 수치로 사용).

우선순위: 3그룹(어르신·청년·다문화) 대상 자원 → 무료 자원 → 나머지. 6주 말까지 전량, 3주 말까지 3그룹분 완료.

## 5. 데이터 최신화 파이프라인

```
[종합안내서 2022] ─POI 1회 변환→ [구글시트 태깅] ─CSV→ [MySQL RESOURCE]
                                                        ▲          │
[복지로 지자체복지서비스 API (시흥시 필터)] ─@Scheduled 주 1회─┤          │
  → 공공 사업 명칭 매칭 대조: 목록에 없으면 '종료 의심' 플래그,  │          ▼
    있으면 last_verified_date 갱신 (SyncService, 권장 기능)     │    [관리자 화면]
[오류 제보] ──────────────────────────────────────────────────┘    등록·수정·숨김
```

- 복지로 API: 공공데이터포털 "한국사회보장정보원_지자체복지서비스(목록·상세조회)" — 자유이용, 활용신청 자동승인 유형. **4주차 내 신청**(승인 실패 시 이 기능만 제외, 다른 경로 영향 없음).
- 민간 544건은 API에 없음 → 제보 + 분기 수동 점검이 공식 경로(운영 절차는 05 문서).
