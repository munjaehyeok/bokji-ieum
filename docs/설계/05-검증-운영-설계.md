# 05. 검증·운영 설계

최종평가 70%는 "실제 구현과 검증 결과"다. 검증은 8주차에 하는 것이지만 **설계는 지금** 해둬야 3주차에 기준선을 잡을 수 있다.

## 1. 매칭 정확도 — 시나리오 6개 (3그룹 × 2)

틀은 지금 확정, '기대 자원' 칸은 3주차 태깅 완료 직후(10/18까지) 종합안내서를 보고 팀 합의로 기입한다. **기대 자원을 먼저 적고 → 매칭을 돌린다** (거꾸로 하면 검증이 아니라 끼워맞추기).

| # | 그룹 | 입력 조건 | 기대 자원 (3주차 기입) | 통과 기준 |
|---|---|---|---|---|
| S1 | 어르신 | 1959년생(67세)·정왕본동·1인가구·기초수급·장애N·내국인 | 노인돌봄·무료급식·건강 등 3~5건 | 기대 자원이 상위 5위 내 |
| S2 | 어르신 | 1954년생(72세)·대야동·1인가구·소득 모름 | (소득조건 자원이 '확인 필요'로 포함되는지 함께 확인) | 〃 |
| S3 | 청년 | 2004년생(22세)·은행동·해당없음·중위100↓·구직 | 청년 심리·자립·구직 지원 | 〃 |
| S4 | 청년 | 2007년생(19세)·배곧1동·대학 재학·소득 모름 | 학업·장학·심리 지원 | 〃 |
| S5 | 다문화 | 1992년생·다문화가구·내국인(결혼귀화)·자녀 2명(가구원: 2014·2021년생) | 본인+자녀별 보육·교육 자원 분리 표시 | 가구원 탭별 기대 자원 포함 |
| S6 | 다문화 | 1996년생·외국인(F)·매화동·구직 | 한국어교육·외국인 취업 지원 (F 태그 71건 중) | 〃 + 외국어 화면 정상 |

- 판정: 6개 중 5개 이상 통과(제안서 M3 완료 기준). 3주차 1차 실행 → 결함 수정 → 7주차 회귀 → 8주차 최종 기록.
- 결정표 단위 테스트 30케이스(03 문서)와 함께 `검증표.md`로 저장, 발표 자료에 결과 표 그대로 사용.

## 2. 효과 지표 측정 설계 (제안서 ①~⑤의 실행 절차)

### ① 퍼널 도달률 — "9명 중 8명" (EVENT_LOG 집계)
```sql
-- 세션별 M(매칭)→D(상세)→A(신청안내 확인) 도달
SELECT COUNT(DISTINCT CASE WHEN event='M' THEN session_hash END) AS 매칭,
       COUNT(DISTINCT CASE WHEN event='D' THEN session_hash END) AS 상세,
       COUNT(DISTINCT CASE WHEN event='A' THEN session_hash END) AS 신청안내
FROM event_log WHERE created_at BETWEEN :시작 AND :끝;
```
'A' 이벤트 정의: 상세 화면에서 전화(tel 클릭)·신청URL 클릭·인쇄 중 1회 이상(버튼에 AJAX 비콘).

### ② 탐색 부담 비교 — 프로토콜 고정
- 과제 3개: (a) "67세 1인가구 어르신이 받을 수 있는 식사 지원 찾기" (b) "22세 취준생 심리상담 지원 찾기" (c) "결혼이민자 한국어교육 신청 방법 찾기"
- 각 참가자에게 시흥시 누리집 vs 복지이음 **순서 교차**(학습효과 상쇄: 절반은 누리집 먼저)
- 측정: 과제 완료 시간(스톱워치), 클릭 수(관찰자 수기), 포기 여부. 목표: 30% 이상 단축.

### ③ 설문 (5점 척도, 과제 직후 · 구글폼)
1. 추천된 복지가 왜 나에게 맞는지 이해할 수 있었다
2. 추천 결과를 신뢰할 수 있다
3. 조건 입력이 쉬웠다
4. 다음에 복지를 찾을 때 다시 쓰고 싶다
5. 주변에 추천하고 싶다
 + 주관식: 가장 불편했던 점 1가지. 목표 평균 4.0 이상.

### 사용성 테스트 운영
- 3그룹 × 3명 = 9명, 11/20~22. 섭외: 가족·지인(어르신 2+@), 교내 유학생/다문화센터(D 섭외 담당, **5주차까지 섭외 확정** — 가장 늦게 터지는 리스크).
- 1세션 25분: 과제 3개 → 설문 → 인터뷰 5분. 동의서(개인정보 미수집·익명) 1장 준비.

## 3. 운영·이관 설계 (정책활용가능성 20점의 증거물)

| 산출물 | 내용 | 시점 |
|---|---|---|
| 관리자 매뉴얼 (3~4쪽) | 자원 등록·수정·숨김, 제보 처리, 분기 점검 절차 | 8주차 |
| 데이터 사전 | RESOURCE 컬럼·코드 정의(02 문서 축약) — 이관 시 인수인계 문서 | 8주차 |
| 갱신 절차서 | 분기: 복지로 API 대조 리포트 확인 → 종료의심 자원 처리 → 기준일 갱신. 수시: 제보 처리 SLA 7일 | 8주차 |
| 협의 제안 1쪽 | 복지정책과(데이터)·정보통신과(시스템) 앞 — 복지온에서 "자격 확인하기" 버튼으로 복지이음 연결하는 상호 연계안 + QR 포스터 시안(주민센터 비치용) | 9주차 |

## 5. 발표(최종)용 숫자 체크리스트 — 구현하면서 쌓아야 나중에 있다

- [ ] 단위 판정 30케이스 통과율, 시나리오 6개 결과표
- [ ] 퍼널: 매칭→상세→신청안내 도달률 (목표 8/9)
- [ ] 비교과제 시간·클릭 단축률 (목표 30%↑)
- [ ] 설문 평균 (목표 4.0↑) + 인용할 주관식 코멘트 1~2개
- [ ] 실 서비스 URL + 배포일(11/19) + Lighthouse 접근성 점수
