# 01. 시스템 아키텍처

## 1. 기술 스택 (수업 고정 + 선택 근거)

| 계층 | 기술 | 버전 | 비고 |
|---|---|---|---|
| View | JSP + JSTL 1.2 + jQuery AJAX | — | `c:out`으로 XSS 기본 방어 |
| Web | Spring MVC | 5.3.x | web.xml + servlet-context.xml (비-Boot, 교재 표준) |
| Persistence | MyBatis | 3.5.x | mybatis-spring 연동 |
| DB | MySQL | 8.0 | utf8mb4 |
| WAS | Apache Tomcat | 9.x | war 배포 |
| 빌드 | Maven | — | 팀 전원 동일 환경 |
| 기타 | Apache POI(엑셀 1회 변환), spring-security-crypto(BCrypt만 사용), Rome/Jsoup(뉴스 RSS, 권장 기능) | | Spring Security 풀 도입은 하지 않음 — 관리자 인증은 인터셉터로 충분 |

> **Spring Boot가 허용되는 경우**: spring-boot-starter-web + mybatis-spring-boot-starter + tomcat-embed-jasper(JSP)로 전환. 설정 XML 전부 삭제되고 2주차 골격 공수가 절반으로 줄어든다. 교수 확인 후 결정 — 이후 문서는 어느 쪽이든 동일하게 적용됨.

## 2. 레이어드 아키텍처

```
브라우저 (JSP + jQuery)
   │  HTTP / AJAX(JSON)
┌──▼──────────────────────────────────────────┐
│ Controller  @Controller / @RestController    │  요청 검증, 세션, i18n
├─────────────────────────────────────────────┤
│ Service     @Service, @Transactional         │  판정 후처리, 로그 기록
├─────────────────────────────────────────────┤
│ Mapper(DAO) MyBatis 인터페이스 + XML          │  매칭 SQL, CRUD
├─────────────────────────────────────────────┤
│ MySQL 8     resource 외 9개 테이블            │
└─────────────────────────────────────────────┘
횡단: LocaleChangeInterceptor(?lang=) · AdminAuthInterceptor(/admin/**)
      FunnelLogInterceptor(상세/신청 조회 익명 로그)
```

## 4. 배포 구성 (8주차 11/19 배포 목표 — 완성도 20점 직결)

```
[사용자] ─ HTTP(S):80/443 ─ [EC2 t3.micro (프리티어, Ubuntu 22.04)]
                              ├─ Caddy (리버스 프록시 + 자동 HTTPS)
                              ├─ Tomcat 9 :8080 (bokji.war)
                              └─ MySQL 8 :3306 (localhost만 바인딩)
도메인: DuckDNS 무료 서브도메인 (예: bokji-ieum.duckdns.org)
백업: mysqldump cron 일 1회 → /backup, 7일 보관
```

- 단일 인스턴스, 분리 없음. 목표 동시 사용자는 사용성 테스트 9명 + 심사위원 수준.
- 배포 절차: `mvn package` → scp war → Tomcat webapps 교체. 스크립트 1개(`deploy.sh`)로 고정, 8주차 전에 5주차 중간 배포 1회 리허설(완료 기준: 실 URL에서 매칭 동작).
- 학교 서버가 제공되면 EC2 대신 사용(Caddy 생략 가능). **4주차까지 둘 중 하나 확정.**

## 5. 보안·개인정보 설계 (경계는 간소화하지 않음)

| 항목 | 설계 |
|---|---|
| SQL Injection | MyBatis `#{}`만 사용. `${}`는 ORDER BY 화이트리스트 1곳 외 금지 |
| XSS | 출력은 전부 `<c:out>`. 자원 content는 관리자 입력이므로 등록 시 태그 제거(Jsoup `clean`) |
| 관리자 인증 | BCrypt 해시, AdminAuthInterceptor로 `/admin/**` 차단, 로그인 5회 실패 시 10분 잠금(세션 기준) |
| CSRF | 관리자 변경 폼에 세션 토큰 hidden 필드(자체 구현 20줄) — 공개 화면은 상태 변경이 제보뿐이라 토큰+횟수 제한으로 충분 |
| 제보 스팸 | 내용 500자 제한, 세션당 5건/일 |
| 개인정보 | 매칭 조건: 세션에만, DB 미저장. 로그: 연령은 10세 밴드·동 단위까지만, IP/식별자 미저장, 세션은 랜덤 해시. 결과 화면 고지 문구 고정: "참고용 안내이며 최종 자격은 담당기관 확인" |
| 비밀값 | DB 비밀번호·API 키는 서버의 `config.properties`(git 제외, `.gitignore`) |

## 6. 협업 규칙 (제안서 확정분의 구체화)

- 브랜치: `main`(배포) ← `dev` ← `feat/M3-matching` 식. PR 리뷰 1인 승인 후 머지.
- `schema.sql` 변경은 반드시 PR로 — DB 스키마가 4명 공통 의존이므로 단톡 공지 동시 진행.
- 주 1회 스크럼(수업 후): 지난주 완료 기준 체크 → 이번 주 산출물 확인 → 지연 시 Should 제외 규칙 적용.
