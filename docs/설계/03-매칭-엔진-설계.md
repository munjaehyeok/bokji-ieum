# 03. 매칭 엔진 설계

## 1. 판정 모델

조건 7종 각각에 대해 자원의 제약(c)과 사용자 입력(u)을 비교해 4가지 중 하나로 판정한다.

| 판정 | 조건 | 처리 |
|---|---|---|
| 무관 | c = NULL (자원이 이 조건을 안 봄) | 점수 제외, 표시 안 함 |
| **일치** | c 있음 ∧ u가 c를 만족 | +가중치, 카드에 초록 태그 |
| **확인 필요** | c 있음 ∧ u = 모름/미입력, 또는 경계·세부기준 애매 | 포함, 주황 태그 |
| **불일치** | c 있음 ∧ u가 c를 명확히 위반 | **결과에서 제외** (WHERE) |

핵심 원칙: **애매하면 제외하지 않고 '확인 필요'로 포함한다.** 받을 수 있는 복지를 안 보여주는 오류(false negative)가 가장 나쁘다.

점수 = Σ(일치 조건 × 가중치). 정렬: 점수 ↓ → 확인필요 수 ↑(적은 것 먼저) → data_base_date ↓.
(보정: 외국어 로케일에서는 동점 시 nationality='F' 자원 우선 — 설계 04 §4 다국어 규정, 정렬 1항으로 구현.)

가중치 (상수, resource-mapper.xml 상단 주석에 고정):

| 조건 | 가중치 | 근거 |
|---|---|---|
| 연령 | 3 | 가장 배타적·판별력 높음 |
| 장애 | 3 | 대상 전용성 강함 |
| 국적(외국인) | 3 | 〃 |
| 가구형태 | 2 | |
| 소득 | 2 | |
| 학업/취업 | 2 | |
| 거주 동 | 1 | 동 제한 자원이 드물고 시 전체가 기본 |

## 2. 조건별 판정 결정표 (구현 명세)

사용자 입력 DTO `MatchCondition`: birthYear, dong, householdTypes(Set), incomeRank(0=모름), disability(Y/N/U), nationality(K/F), eduWork(Set, 비면 해당없음), members(List, 권장).

### ① 연령 — 경계 ±1세 관용 규칙
- 나이 = 당해연도 − 출생연도 (만 나이 오차 ±1 내재 → 아래 관용으로 흡수)
- `age ∈ [min, max]` → 일치
- `age ∈ [min−1, min)` 또는 `(max, max+1]` → **확인 필요** ("연령 경계: 생일에 따라 가능")
- 그 외 → 불일치 / 출생연도 미입력 → 확인 필요

### ② 거주 동
- dong_codes IS NULL → 무관 | u 포함 → 일치 | u=모름/미선택 → 확인 필요 | 미포함 → 불일치

### ③ 가구형태 — 교집합 존재 → 일치, u=해당없음 → 불일치, u 미선택 → 확인 필요

### ④ 소득 (u: 0모름 / 1수급 / 2차상위 / 3중위100이하 / 4그이상)

| | c=1 수급만 | c=2 차상위↓ | c=3 중위100↓ | c=4 중위150↓ |
|---|---|---|---|---|
| u=1 | 일치 | 일치 | 일치 | 일치 |
| u=2 | 불일치 | 일치 | 일치 | 일치 |
| u=3 | 불일치 | 불일치 | 일치 | 일치 |
| u=4 | 불일치 | 불일치 | 불일치 | **확인 필요** (150 이하인지 모름) |
| u=0 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 |

- 추가: income_uncertain='Y'면 '일치'여도 확인필요 태그 병기("소득 세부기준 확인").

### ⑤ 장애 — c='Y': u=Y 일치 / u=N 불일치 / u=U 확인 필요

### ⑥ 국적 — c='F': u=F 일치, u=K 불일치. c='K': u=K 일치, u=F **확인 필요**(외국인등록·거소신고로 가능한 사업 존재 → 제외하지 않음)

### ⑦ 학업/취업 — 교집합 → 일치, u=해당없음 → 불일치, 미선택 → 확인 필요

### 공통
- uncertain_note 있으면 무조건 확인필요 태그 1개 추가.
- data_base_date가 12개월 경과 → '자료 기준일 확인' 뱃지(판정과 별개, 카드·상세에 표시).

### 판정 보충 규정 (2026-10-13 확정 — QA 설계 질의 5건에 대한 판정)

| # | 질의 | 확정 |
|---|---|---|
| Q1 | 가구형태·학업/취업에서 "사용자가 선택했으나 교집합 없음" | **불일치(제외)** — 명시 선택은 명확한 정보이므로 결정표 의도대로 제외 |
| Q2 | 학업/취업·가구형태의 '해당없음' vs '모름' 구분 | 입력값 3상태로 확정: **빈 값(미선택/건너뛰기)=모름→확인필요**, **명시적 'NONE'(해당없음)=제약 자원 불일치**, 그 외=선택값. DTO의 Set에 'NONE' 특수값 사용 |
| Q3 | age_min만 또는 age_max만 있는 자원 | 없는 쪽은 무제한 (COALESCE 0 / 200) — 잠정안 그대로 확정 |
| Q4 | 국적 '모름' | 국적은 '모름' 없음 — 입력 필수, 기본값 K. 결정표에서 국적의 u=모름 행은 존재하지 않는 것으로 확정 |
| Q5 | income_uncertain='Y' ∧ u=0(모름) | INCOME(모름) 확인필요 태그만 표시, **INCOME_DETAIL 중복 병기 안 함** (일치일 때만 INCOME_DETAIL) |

## 3. 매칭 SQL — 쿼리 한 방 설계 (MyBatis)

제외(WHERE) + 점수(SELECT) + 추천 이유(matched/needCheck CSV)를 단일 쿼리로 산출. 744건 풀스캔이라 성능 문제 없음.

```sql
SELECT r.*,
  /* 점수 */
  ( CASE WHEN r.age_min IS NULL AND r.age_max IS NULL THEN 0
         WHEN #{age} IS NULL THEN 0
         WHEN #{age} >= COALESCE(r.age_min,0) AND #{age} <= COALESCE(r.age_max,200) THEN 3
         ELSE 0 END
  + CASE WHEN r.dong_codes IS NOT NULL AND #{dong} IS NOT NULL
          AND FIND_IN_SET(#{dong}, r.dong_codes) THEN 1 ELSE 0 END
  + CASE WHEN r.household_types IS NOT NULL AND #{hhCsv} IS NOT NULL
          AND EXISTS_INTERSECT(r.household_types, #{hhCsv}) THEN 2 ELSE 0 END   -- ↓각주
  + CASE WHEN r.income_rank IS NOT NULL AND #{incomeRank} BETWEEN 1 AND 4
          AND #{incomeRank} <= r.income_rank THEN 2 ELSE 0 END
  + CASE WHEN r.disability='Y' AND #{disability}='Y' THEN 3 ELSE 0 END
  + CASE WHEN r.nationality IS NOT NULL AND r.nationality=#{nationality} THEN 3 ELSE 0 END
  + CASE WHEN r.edu_work IS NOT NULL AND #{ewCsv} IS NOT NULL
          AND EXISTS_INTERSECT(r.edu_work, #{ewCsv}) THEN 2 ELSE 0 END
  ) AS score,
  /* 추천 이유: 일치 태그 CSV */
  CONCAT_WS(',',
    CASE WHEN (r.age_min IS NOT NULL OR r.age_max IS NOT NULL) AND #{age} IS NOT NULL
          AND #{age} BETWEEN COALESCE(r.age_min,0) AND COALESCE(r.age_max,200) THEN 'AGE' END,
    CASE WHEN r.dong_codes IS NOT NULL AND FIND_IN_SET(#{dong}, r.dong_codes) THEN 'DONG' END,
    /* ... 조건별 동일 패턴 ... */ ) AS matched_csv,
  /* 확인 필요 태그 CSV */
  CONCAT_WS(',',
    CASE WHEN (r.age_min IS NOT NULL OR r.age_max IS NOT NULL) AND (#{age} IS NULL
          OR #{age} = COALESCE(r.age_min,0)-1 OR #{age} = COALESCE(r.age_max,200)+1) THEN 'AGE' END,
    CASE WHEN r.income_rank IS NOT NULL AND (#{incomeRank}=0
          OR (#{incomeRank}=4 AND r.income_rank=4)) THEN 'INCOME' END,
    CASE WHEN r.income_uncertain='Y' AND #{incomeRank} BETWEEN 1 AND 3 THEN 'INCOME_DETAIL' END,
    CASE WHEN r.nationality='K' AND #{nationality}='F' THEN 'NATIONALITY' END,
    CASE WHEN r.uncertain_note IS NOT NULL THEN 'NOTE' END,
    /* ... */ ) AS need_check_csv
FROM resource r
WHERE r.status = 'A'
  /* 불일치 제외 — 판정 결정표의 '불일치' 행만 여기 온다 */
  AND (r.age_min IS NULL OR #{age} IS NULL OR #{age} >= r.age_min - 1)      -- ±1 관용
  AND (r.age_max IS NULL OR #{age} IS NULL OR #{age} <= r.age_max + 1)
  AND (r.dong_codes IS NULL OR #{dong} IS NULL OR FIND_IN_SET(#{dong}, r.dong_codes))
  AND (r.household_types IS NULL OR #{hhCsv} IS NULL
       OR EXISTS_INTERSECT(r.household_types, #{hhCsv}))                    -- 해당없음은 hhCsv='' 로 전달
  AND (r.income_rank IS NULL OR #{incomeRank} = 0
       OR #{incomeRank} <= r.income_rank
       OR (#{incomeRank} = 4 AND r.income_rank = 4))
  AND (r.disability IS NULL OR #{disability} <> 'N' OR r.disability IS NULL)
  AND (r.nationality IS NULL OR r.nationality = #{nationality}
       OR (r.nationality = 'K' AND #{nationality} = 'F'))                   -- K자원·외국인은 확인필요로 포함
  AND (r.edu_work IS NULL OR #{ewCsv} IS NULL OR EXISTS_INTERSECT(r.edu_work, #{ewCsv}))
  <if test="category != null"> AND r.category = #{category} </if>
ORDER BY score DESC,
         (LENGTH(need_check_csv) - LENGTH(REPLACE(need_check_csv, ',', ''))) ASC,
         r.data_base_date DESC
```

주석(구현 시 결정):
- `EXISTS_INTERSECT(a, b)`: MySQL에 없음 → CSV 2개의 교집합 검사. 구현은 ① 사용자 쪽 선택지를 MyBatis `<foreach>`로 풀어 `FIND_IN_SET(#{item}, r.household_types)` OR 체인 (권장, 표준적) ② 저장을 SET 타입으로 바꿔 `r.household_types & #{bitmask}` 중 택1. **①로 간다** — 디버깅이 쉽고 수업 범위 기술.
- `need_check_csv`를 ORDER BY에서 재사용 못 하면(별칭 제약) 서브쿼리로 감싼다.
- 가중치·판정 변경은 이 XML 한 파일만 수정하면 되도록 유지(로직을 Java로 복제 금지).

## 4. Service 후처리

```
MatchService.match(cond):
  rows = resourceMapper.findMatches(cond)
  각 row: matched_csv/need_check_csv → 다국어 라벨 리스트로 변환 (messages.properties 키: tag.AGE 등)
  MATCH_LOG insert (익명: age→10세 밴드 변환)
  return rows
```

## 5. 가구원 단위 매칭 (권장 M-확장, 스키마 변경 없음)

- 입력 화면에서 "가구원 추가"(관계·출생연도·장애 등) → 세션의 `List<MatchCondition>`.
- 가구 공통 조건(동·소득·가구형태)은 본인 값 복사, 개인 조건(나이·장애·학업)만 가구원별.
- 같은 쿼리를 인원수만큼 호출 → 결과 탭 "나 / 자녀1 / …"로 구분 표시. 744건 × N회 쿼리로 충분.

## 6. 단위 검증 (3주차 산출물)

판정 결정표의 모든 칸(약 30케이스)을 `match_test.sql` + 기대결과 표로 작성, 시나리오 6개(05 문서)와 함께 7주차 회귀 테스트에 재사용. 결정표 ↔ SQL 불일치가 이 프로젝트 최대 리스크이므로, **SQL 작성자(A)가 아닌 C가 결정표 기준으로 검수**한다.
