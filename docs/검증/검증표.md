# 검증표 — 시나리오 S1~S6 (설계/05 §1 틀)

- 실행일: 2026-10-13 / 실행자: qa-verifier
- 절차 준수: **기대 자원 선정(§1, DB LIKE 검색) → 매칭 실행(§2, HTTP)** 순서로 작성. 기대 선정 시 매칭 쿼리·결과 미참조(자원의 name/eligibility 검색 + 태깅 컬럼 확인만).
- 환경: TEST- fixture 제거 완료 상태(`SELECT COUNT(*) FROM resource` = 744) 에서 실행 — GATE 2와 분리.
- 입력 규약: 시나리오에 명시되지 않은 필드는 모름/미입력(빈 값·U·incomeRank 0), 국적은 기본 K. 나이 = 2026 − 출생연도.
- **동점 처리 규칙(사전 선언)**: 표시 순위 기준 상위 5위 판정. 단, 기대 자원의 정렬 키(score, 확인필요 태그 수)가 5위 자원의 정렬 키와 **같으면** 동순위로 간주해 '5위 내'로 판정한다(data_base_date는 전 자원 동일(2022-12-31)이라 변별력 없음).
- 시나리오 통과 기준: **설계 05 §1 문언 그대로** — S1~S4·S6: 기대 자원이 상위 5위 내(동점 규칙 적용) 존재 ∧ 기대 자원 전원이 결과 목록에 포함(제외 0건 — false negative 금지), S5: 가구원 탭 분리 + 탭별 기대 자원 포함, S6: + 외국어 화면 정상. 전체 통과 기준: 6개 중 5개 이상(설계 05).
- 투명성 기록: QA 초안은 "기대 자원 중 2건 이상 상위 5위 내"라는 더 엄격한 자체 기준을 선언했으나, 이 기준은 설계 05가 S5·S6에 별도 기준(포함/탭·화면)을 둔 것과 충돌해 **설계 문언 기준으로 판정을 확정**한다. 참고로 엄격 기준(2건) 적용 시 결과도 §2 각 행에 "상위5 내 기대 자원 수"로 병기한다(S4=1건·S6=1건으로 엄격 기준 미달 — 숨기지 않고 기재).

- **단, 최소 뷰(result.jsp)의 정적 문구("매칭 결과", "일치:", "확인 필요:", "~개의 복지가 조건과 맞습니다")는 한국어 고정** — 해당 JSP는 "기능 검증용 최소 뷰, 디자인 금지(프론트 교체 예정)" 명시 파일로, 정적 문구 i18n은 프론트(8081) 작업분. 백엔드 i18n 파이프라인(번역 조인·라벨 변환·정렬 보정)은 정상.

**판정: PASS** — 상위 5위 내 기대 자원 1건(1위), 전원 포함, 외국어 데이터·라벨 정상. (상위5 내: 1 — 엄격 2건 기준 미달. F 태그 자원은 연령 태깅이 없어 3점대에 머물고, 비 F 자원 중 연령+학업취업 5점 동점이 다수. 뷰 정적 문구 건은 프론트 이관 항목으로 별도 기재.)
